## 搬了什么

`git mv` 到 `backend/translation/retainpdf_translation/`：`artifacts/`、`core/`、`llm/`、`prompts/`、`public/`、`services/`、
`workflow/`、`prompt_loader.py`；`translate/README.md` → `backend/translation/README.md`。

留在 `backend/pipeline/retainpdf_pipeline/translate/` 的是 worker 外壳：`__init__.py`、`__main__.py`、`entrypoints/`、
`translation_stage.py`，另加一份说明外壳是什么的 `README.md`。Rust 启动的 `python -m retainpdf_pipeline.translate` 不变。

新包 `backend/translation`（`retainpdf-translation`）：

- 依赖 `retainpdf-base`、`retainpdf-math`、`requests`、`urllib3`、`PyMuPDF`（领域推断读源 PDF 前几页），版本和流水线一致
- package-data：`retainpdf_translation.prompts` 的 `*.txt`（原来登记在流水线的 pyproject 里，跟着搬过来）、QA 报告的 schema
- `tests/test_package.py`：不 import 流水线、`public` 在流水线不可导入时也能用、提示词都能读到

## 改引用

约 430 个文件里的 `retainpdf_pipeline.translate.<库目录>` 机械替换成 `retainpdf_translation.<…>`，带 `backend/` 前缀的
路径同样替换；不带前缀的相对路径逐个看过。历史规划文档和开发记录不改。

Rust 两处：`retainpdf-core` 的 `models/input/translation.rs` 两个 `include_str!`（只在 `#[cfg(test)]` 里，Docker 构建不受影响）、
`api_tests/model_executor.rs` 内嵌的 Python import。另有 3 个文件只改了注释里的 Python 路径：`retainpdf-core` 的 `storage_paths/job_paths.rs`、`retainpdf-jobs` 的
`reports/usage/mod.rs`、`retainpdf-providers` 的 `provider_probe/deepseek.rs`。其余 Rust 里的 `retainpdf_pipeline.translate`
都是 worker 模块名，不动。

## 架构门禁

`check_pipeline_architecture.py` 的翻译规则原来都以 `retainpdf_pipeline/translate/` 为根、以 `retainpdf_pipeline.translate.`
为模块前缀。只替换字符串不够：层级规则只检查 `startswith("retainpdf_pipeline.translate.")` 的 import，替换以后翻译内部的
import 全换成了 `retainpdf_translation.`，规则会**悄无声息地全部放行**。逐条改了：

- `common.py`：加 `TRANSLATION_PACKAGE_ROOT`；`rel()` 对流水线外的文件改成相对 `backend/`，所以按路径登记的名单
  （payload 字段 writer、原文读取点、副本配对）里翻译的文件写成 `translation/retainpdf_translation/...`
- `translation_rules.py`：`TRANSLATION_ROOT` 指向翻译包，新加 `TRANSLATION_SHELL_ROOT`（worker 外壳）；
  包根目录只许 `__init__.py`、`prompt_loader.py`，外壳只许 `__main__.py`、`README.md`、`entrypoints/`、`translation_stage.py`；
  `entrypoints` 层规则改为作用在外壳的 `entrypoints/` 上
- 层级规则、workflow 子包规则改认 `retainpdf_translation.` 前缀；`public/` 懒加载检查改查 `retainpdf_translation.` 的 eager import
- `check_translation_library_self_contained`：翻译包不许 import 任何 `retainpdf_pipeline.*`（含外壳）
- OCR provider 的禁止名单加上 `retainpdf_translation`；渲染、OCR 分离检查和 decision_diff 检查的扫描范围加上翻译包
- 阶段契约副本门禁（`stage_contract_duplicates.py`）两个包都扫、两种模块名都认（渲染抄翻译的 payload 契约、翻译抄
  document_schema 的词表）
- 删掉 `TRANSLATION_RENDERING_IMPORT_EXCEPTIONS` 里早已不存在的渲染预热例外

**故意写违规验证过**：往真实代码里写了 8 处违规（报出 10 条）——翻译包 import 渲染、payload 层 import workflow、memory 层 import
provider_runtime、外壳里加文件、渲染直接 import 翻译 core、OCR provider import 翻译包、翻译包里直接写
`should_translate`、改翻译那份 `BLOCK_CLASSES` 副本——每一处都报出来了，恢复后门禁通过。

## 打包

tests」一步）、`dev.sh` 的 `PYTHONPATH`、源码归档的必备文件、独立运行检查（import 并读一条提示词，确认提示词进了 wheel）、
`resolve_backend_source.py`。依赖报告重新生成（流水线多了一个依赖 `retainpdf_translation`）。
