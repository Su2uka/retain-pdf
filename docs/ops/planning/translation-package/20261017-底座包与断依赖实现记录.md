## 要注意的两处

- **本地密钥目录不能跟着文件走。** `local_env` 原来用 `Path(__file__).parents[3] / ".env"` 定位，算出来是
  `backend/pipeline/.env`；挪进 `backend/base/retainpdf_base/` 以后同样的写法会指到 `backend/.env`。改成
  `parents[2] / "pipeline" / ".env"`，仍是 `backend/pipeline/.env`（`.gitignore`、文档、前端冒烟脚本都写的这个位置），
  `backend/base/tests/test_base.py` 钉住了。
- **`paths` 找仓库根的写法不受影响**：它从文件位置往上找 `backend/pipeline` 和 `contracts`，在 `backend/base` 下一样能找到。

## 底座包

`backend/base`（`retainpdf-base`，`import retainpdf_base`），uv workspace 成员，只依赖标准库；
`test_base_only_depends_on_the_standard_library` 检查它不 import 任何 `retainpdf_*` 包。流水线依赖它。

打包照 `retainpdf-math` 那次的清单加上：

- `backend/pyproject.toml`、`backend/pipeline/pyproject.toml`、`backend/uv.lock`（重新 lock，只多了 `retainpdf-base` 一项）
- Docker 镜像：复制 `pyproject.toml` 给 `uv export`，复制源码并在 pipeline 之前 `pip install --no-deps`
- 三个平台的桌面包：在 pipeline 之前从源码装（`--no-deps`）；Windows 的 import 检查加上 `retainpdf_base`；
  `test_desktop_release_build_contracts.py` 加了「先装底座包」的断言
- CI：import 检查加上 `retainpdf_base`，加「Base package tests」一步
- `ops/development/dev.sh` 的 `PYTHONPATH`、`ops/release/build_source_archive.py` 的必备文件、
  `ops/release/check_standalone.py` 的 import 检查、`.github/scripts/resolve_backend_source.py`
- requirements 生成脚本会自动排除 workspace 包，不用改；依赖报告重新生成

## 门禁

`check_pipeline_architecture.py` 加了 `check_translation_library_self_contained`：`translate/` 下除了 worker 外壳
（`__main__.py`、`entrypoints/`、`translation_stage.py`）以外的文件，不许 import `retainpdf_pipeline.translate` 以外的
`retainpdf_pipeline.*`，也不许 import 外壳。规则常量在 `translation_rules.py` 的 `TRANSLATION_WORKER_SHELL`、
`TRANSLATION_SHELL_MODULES`；`test_translation_layer_gate.py` 加了 8 条用例（允许底座包、公式包、翻译自己；
拒绝 `stage_specs`、`render`、外壳；外壳本身可以依赖流水线）。

`translation_boundaries.py` 里 workflow 子包规则原来认 `retainpdf_pipeline.services.pipeline_shared.` 前缀，
改成认 `retainpdf_base.`。
