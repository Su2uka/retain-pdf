# 第 1 期：前端在调、契约里还没有 `client_name` 的接口

第 0 期把书库的 17 个接口换成了生成的函数（`frontend/packages/api/src/generated/library-documents.ts`）。
这份清单是第 1 期的输入：前端实际调用的接口逐个对过契约端点表和 `backend/api/docs/routes.txt`，
分出“契约里已有、只差起名”和“契约里没有”两类，按先后排好，交给后端补契约。

盘点范围：`frontend/packages/{api,reader,domain}/src`、`frontend/web/src`、`frontend/desktop/src`（2026-10-22，main `b9508d3e`）。

## 1. 总数

- 前端封装了 111 个接口（不算第 0 期生成的 17 个），其中 5 个写了封装但没有调用方（见第 6 节）。
- 全部能在 `routes.txt` 里找到，没有调用旧地址的。
- 契约里已经有、只差 `client_name` 的 30 个；契约里没有的 81 个。

| 类 | 个数 | 怎么处理 |
|---|---|---|
| 契约已有：任务、阅读数据、用量 | 16 | **1a**，后端只补 `client_name` |
