## 一些实现上的决定

- **旧地址全部保留**，内部和新地址走同一个出口。快照里旧地址的条目一个字没变。
- **后端返回给前端的链接这次没换**（任务详情、书籍详情里的 `pdf_url`、`markdown_url`、
  `cover_url`、产物清单的 `resource_url` 等仍是旧地址）。原因见下面"前端要改的地方"第 1 条：
  前端有按旧地址的样子推算别的地址的代码，后端先换会把它弄坏。等前端改完再换。
- AI 服务里存下来的旧对话记录里有旧的图片地址，后端两种都认，所以过滤两种都放行。
- **防止退回去**：`check_architecture.py` 的 `check_artifact_path_ownership`。只有出口模块
  （`services/jobs/downloads`、`services/library/media.rs`、`services/artifacts`、
  `services/derived_artifacts`）能调 `storage_paths::resolve_*` 拼产物路径。另外 12 个文件是
  现状，冻结在 `KNOWN_ARTIFACT_PATH_READERS`：只许删、不许加，删掉以后名单里还留着也报错。

## 前端要改的地方（后端不改前端代码，列在这里给前端）

按代码搜索整理，改之前请再核一遍。

1. **`features/book-detail/domain/artifact-resources.ts`**：Word 的地址是把译文 PDF 链接结尾的
   `/pdf` 换成 `/docx` 推出来的。改成直接用 `/jobs/{id}/files/output/translated.docx`，
   或者从 `GET /jobs/{id}/files` 的清单里取。**这条要先改**，后端才能把返回的链接换成新地址。
2. **`features/reader/domain/dialog/runtime-port.ts`**：自己拼 `/jobs/{id}/pdf` 和
   `/jobs/{id}/pdf/side-by-side` → `/files/output/translated.pdf`、`/files/output/side-by-side.pdf`
   （要下载的加 `?download=1`）。
3. **`features/reader/domain/host/data.ts`**：`/documents/{id}/source.pdf` → `/documents/{id}/files/source.pdf`。
4. **`features/book-detail/ui/use-book-detail-artifact-center.ts`**：兜底拼的 `/markdown`、
   `/markdown?raw=true`、`/pdf` → `/files/output/ocr.md`、`/files/output/translated.pdf`。
5. **产物列表**（`features/job-detail/domain/page/artifacts.ts`、书籍详情的资源列表）：现在读
   `/artifacts-manifest`，按旧产物名排序、显示。可以改成读 `/jobs/{id}/files`，按 output / internal
   分组显示。多用户模式下网站账号的清单里没有 `internal`，中间产物那一栏会是空的，这是有意的。
6. 封面、缩略图统一用 `/documents/{id}/files/cover.jpg`、`thumbnail.jpg`。
7. 新地址默认在浏览器里打开，要下载的地方加 `?download=1`。旧地址里有的默认就是下载
   （`/pdf/side-by-side`、`/docx`、`/download`），换的时候注意。
