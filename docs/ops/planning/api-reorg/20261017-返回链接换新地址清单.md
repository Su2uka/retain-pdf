# 返回链接换新地址清单

> 日期：2026-10-17
> 起因：[文件出口实现记录](./20261015-文件出口实现记录.md)的"还没做"第 1 条；前端 2026-10-17 说"可以换返回链接了"
> （前端不再从 `pdf_url` 推导 Word、对照版，新旧两种链接都认），用户同意。
> 新地址见[任务与文件接口整理](./20261015-任务与文件接口整理.md)第 2、3 节。

后端返回的 JSON 里带的链接，从旧地址换成新地址。**旧地址照样能用，一个都不删**：
- 已经存下来的旧链接（前端缓存、AI 对话记录里的图片地址）照样能打开；
- 删旧地址是以后的事，要先看访问统计。

换的原则：
- 新旧地址返回的东西一样，就直接换；
- 旧地址默认下载、新地址默认在浏览器里打开的，新链接后面加 `?download=1`，保持原来的行为。

## 1. 直接换（返回的内容一样）

`{id}` 是任务编号，`{doc}` 是书（文档）编号，前缀都是 `/api/v1`。

| 字段 | 在哪里返回 | 旧 | 新 |
|---|---|---|---|
| `pdf_url`、`pdf.path`/`pdf.url`、`actions.download_pdf` | 任务详情、列表的 `artifacts`、书籍详情 | `/jobs/{id}/pdf` | `/jobs/{id}/files/output/translated.pdf` |
| `markdown.raw_path`/`raw_url`、`actions.open_markdown_raw` | 同上 | `/jobs/{id}/markdown?raw=true` | `/jobs/{id}/files/output/ocr.md` |
| `markdown_images_base_url`、`markdown.images_base_path`/`images_base_url` | 同上 | `/jobs/{id}/markdown/images/` | `/jobs/{id}/files/output/ocr/images/` |
| `bundle_url`、`bundle.path`/`bundle.url`、`actions.download_bundle` | 同上 | `/jobs/{id}/download`（下载） | `/jobs/{id}/files/output/all.zip?download=1` |
| `actions.cancel` | 同上 | `/jobs/{id}/cancel` | `/jobs/{id}/actions/cancel` |
| `links.events_path`/`events_url` | 建任务的返回、任务详情的 `links` | `/jobs/{id}/events` | `/jobs/{id}/progress/events` |
| `links.cancel_path`/`cancel_url` | 同上 | `/jobs/{id}/cancel` | `/jobs/{id}/actions/cancel` |
| `actions.rerun` | 同上 | `/jobs/{id}/rerun` | `/jobs/{id}/actions/rerun` |
| 重试阶段的 `action.url` | `GET /jobs/{id}/actions`（旧 `/stage-actions`） | `/jobs/{id}/retry-stage` | `/jobs/{id}/actions/retry-stage` |
| `ocr_job.detail_path`/`detail_url` | 任务详情 | `/ocr/jobs/{ocr_id}` | `/jobs/{ocr_id}` |
| Markdown 视图里的 `raw_path`/`raw_url`、`images_base_*`、`images[].url`，`content_with_absolute_image_urls` 里的图片地址 | `GET /jobs/{id}/reader/markdown`、旧 `/markdown` | 同上面 Markdown 几行 | 同上面 Markdown 几行 |

## 2. 换成新地址，但有一点不一样

| 字段 | 旧 | 新 | 不一样的地方 |
|---|---|---|---|
| `normalized_document_url`、`normalized_document.*`、`normalization_report_url`、`normalization_report.*` | `/jobs/{id}/normalized-document`、`/normalization-report` | `/jobs/{id}/files/internal/normalized-document.json`、`normalization-report.json` | 内容一样。多用户模式下 `internal/` 只给管理员，旧地址网站账号也能取。多用户已经停了，单用户没有区别 |
| `markdown_url`、`markdown.json_path`/`json_url`、`actions.open_markdown` | `/jobs/{id}/markdown`（`{code, data: {content, raw_url, ...}}`） | `/jobs/{id}/reader/markdown` | 新地址返回的是 Markdown 视图，字段更全（多了 `images`、`content_with_absolute_image_urls`），外面没有 `{code, data}` 那一层。前端只把它显示成链接、在新标签打开，不解析；书籍详情的兜底本来就是 `/reader/markdown` |

## 3. 这次不换

| 字段 | 留在旧地址的原因 |
|---|---|
| `manifest_path`/`manifest_url`（`/artifacts-manifest`）、`actions.open_artifacts`（`/artifacts`）、`links.artifacts_*`、`links.artifacts_manifest_*` | 新的 `/jobs/{id}/files` 返回的结构不一样，前端下一轮才改成读 `/files` |
| 产物清单里 `source_pdf` 的 `resource_path`（`/artifacts/source_pdf`） | 原文在书下面（`/documents/{doc}/files/source.pdf`），任务的清单里不一定有书编号；前端下一轮和 `/files` 一起迁 |
| 没有书编号的书的 `cover_url`、`thumbnail_url`（`/library/books/{id}/cover`） | 新地址只有按书编号的，没有书编号的旧书只能走旧地址 |

## 4. 前端要做的

- 第 1 节：前端照着返回的链接请求，自动跟上，不用改。
- 第 2 节：看一眼。
  - `normalized_document_url` 那几个是开发者面板在用；
  - `markdown.json_url` 只是显示和打开。
- 有没有哪个字段，前端会自己去拆路径（比如拿 `/pdf` 结尾判断类型）？有的话告诉后端，这个字段先不换。

## 5. 前端的确认（2026-10-17）

前端逐个查过这些字段在前端怎么用，回复"可以，全部照清单换"，没有会拆旧路径的地方。它特别提醒两点，实现里都满足：
- **产物清单里的目录项**（`job_root`、`translations_dir`、`provider_raw_dir` 等）：前端靠 `artifact_kind` 是 `dir` 或路径以 `/` 结尾来跳过。
  这些项没有新文件名，链接还是旧的 `/artifacts/<名字>`，不加 `?download=1`，`artifact_kind` 也没动。
- **Markdown 就绪时 `raw_url` 一直都有**：前端下载 Markdown 时按 `raw_url` → `raw_path` → `markdown_url` 的顺序取。

## 6. 实现

分支 `refactor/api-new-links`（接在 `refactor/crate-library` 后面）。

- **拼新地址的函数放在 retain-core**：新加的 `models/view/file_paths.rs`。任务详情、书籍详情、Markdown 视图、文档列表都调它，不各写一份字符串。
- **`internal/` 的文件名表往下放**：新文件名 ↔ 产物名原来写在任务包的 `files/downloads/catalog.rs`。
  产物清单的 `resource_path` 在 retain-core 里拼，也要用这张表，所以挪到 retain-core 的 `JOB_INTERNAL_FILES`，文件出口照旧从这里查。
- **另外换了两个字段**：`links.events_*` → `/progress/events`，`links.cancel_*` → `/actions/cancel`。
  - 这两个是建任务的返回、任务详情的 `links` 里的，清单初稿漏了；
  - 新旧地址是同一个处理函数，前端不读这两个字段；
  - 已补进第 1 节的表。
- **文件出口快照** `file-responses.txt` 重新生成。102 行改动全是链接字段，加上的每一行都是新地址；文件内容、状态码、下载文件名都没变。
- 12 个测试里写死的旧链接改成新链接。故意请求旧地址、确认它还能用的测试没改。
- `backend/api/docs/api-spec/`、`OCR_Service_API.md`、`docs/api/` 里的返回示例跟着换；接口本身的说明（旧地址还在）没动。
