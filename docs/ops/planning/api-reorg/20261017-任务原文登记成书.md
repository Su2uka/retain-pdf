# 任务原文登记成书

> 日期：2026-10-17
> 分支：`feat/job-source-documents`（接在 `main` 0d8a73ac 后面）
> 起因：旧地址盘点后，前端还剩一个旧地址 `/jobs/{id}/artifacts/source_pdf`，给"查不到书编号的任务"兜底取原文

## 决定

用户 2026-10-17 定：照推荐做，**给没有书编号的任务补上书编号**，不另开一个按任务取原文的地址。
原文是书的文件（[任务与文件接口整理](./20261015-任务与文件接口整理.md)第 3.2 节），补上以后：
- 任务的原文都走书的地址 `/documents/{书编号}/files/source.pdf`；
- 按任务取原文的旧地址，等删旧地址那一轮去掉。

## 哪些任务没有书

书的编号就是原文 PDF 的 sha256。三种任务原来就有书：
- 有上传记录的任务，建任务时就归属到书了（`link_job_to_document`）；
- 从别的任务派生的任务（重新渲染、重试、续跑），继承源任务的书；
- 启动时的回填（`backfill_job_document_links`）按上传、按源任务补过一遍。

剩下的是**从 `source_url` 建的任务**：原文是 OCR 服务商那边拿到的（MinerU 从结果包里取，Paddle 按地址下载），没人给它记上传，
所以一直没有书。前端、AI 服务、命令行都不走这条路，只有直接调 API 的会用。本地两个库（单机、多用户测试）里现在一个都没有。

## 做法

运行器新加 `job_runner/source_document.rs` 的 `adopt_job_source_document`，做法和上传一样：
- 读原文 PDF，算 sha256，就是书的编号；
- **已经有同样内容的上传**（同一个 PDF 别处传过）：书已经在了，任务直接归属过去，不再复制；
- **没有**：
  - 原文复制进上传目录，记一条上传和书，任务归属到这本书；
  - 复制而不是指向任务目录，是因为删任务会删任务目录，书的原文不能跟着没了；
  - 页数用 lopdf 真数一遍，因为上传记录里的页数就是书的页数，存 0 也算数；
  - 多用户下上传和书记在任务的主人名下。

三个时机调它：
1. **OCR 拿到原文、写进任务以后**（`ocr_flow`）：任务还在跑，书架、文件清单里就有原文了。翻译任务的 OCR 子任务登记以后，父任务也归到这本书。
2. **任务结束时**（`lifecycle::job_document`）：前两条路都没找到书时补一次。
3. **rust_api 启动时**（`app/jobs.rs`，`build_state` 里）：给已有的老任务补。没有原文文件的任务跳过，单个任务失败只记日志，不挡启动。

数据库这边新加两个查询：
- 按内容哈希找上传 `upload_with_content_hash`；
- 还没归属到书的任务 `jobs_without_document`。

## 补完以后

- 有原文文件的任务一定有书编号，文件清单里 `source.url` 一定是书的地址。
- 前端取原文时最后那个 `/artifacts/source_pdf` 兜底可以去掉：没有书编号就是没有原文。
- 后端文件清单的 `source` 在没有书编号时还留着旧地址兜底，等删旧地址那一轮一起去掉。

## 测试

运行器新加 3 个：
- 下载来的原文登记成一本书：
  - 原文复制进上传目录，页数是真数的；
  - 删掉任务目录，书的原文还在；
  - 再登记一次是空操作。
- 同一个 PDF 已经有上传：直接归属过去，只有一份文件。
- 没有原文文件的任务：不登记；启动时的批量登记只处理有原文的。

另外把运行器测试里拼 `AppConfig` 的那段挪进 `test_support::test_app_config`，进程运行器的测试和这次的测试共用。
