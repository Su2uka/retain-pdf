## 做了什么

任务领域拆成第八个领域包 `retain-pdf-jobs`，放在 `backend/packages/retain-pdf-jobs`。它管任务的全部：
- 按 9 类分的业务逻辑：任务、操作、进度、文件、报告、阅读、译文、数据、AI；
- 建任务（`submit_job`、`relaunch_in_place`）、校验、发射；
- 任务的文件出口 `files/downloads`；
- 运行时接缝 `runtime_gateway`，质量报告，模型用量。

照样板做：
- 整个目录挪过去，`mod.rs` 改名 `lib.rs` 当门面；
- 路径改成直接写包名：
  - `retain_pdf_api_base::{error, job_loading}`；
  - `retain_pdf_core::{models, config, storage_paths, job_failure}`；
  - `retain_pdf_data::{db, job_events, ocr_provider, worker_command}`；
  - `retain_pdf_runner::job_runner`、`retain_pdf_proc`；
  - 别的领域写 `retain_pdf_files`、`retain_pdf_providers`、`retain_pdf_accounts`、`retain_pdf_ingest`、`retain_pdf_glossaries`；
  - 包里原来的 `crate::services::jobs::…` 改成 `crate::…`，`pub(in crate::services::jobs)` 改成 `pub(crate)`；
- 门面导出的东西改成 `pub`，rust_api 用到的方法、字段也改成 `pub`（构造函数、`JobDownloads::open`、`JobStageViewProjection` 的字段等），
  其余照旧是 `pub(crate)`；
- rust_api 里写 `pub(crate) use retain_pdf_jobs as jobs;` 接上，路由、装配、书库里原有的 `crate::services::jobs::…` 一行没改；
- 加进 `EXTRACTED_DOMAINS`、工作区成员、`Dockerfile.app` 的两个阶段、合并前的 `cargo test`。

依赖和 `ALLOWED_DOMAIN_DEPENDENCIES` 登记的一样：任务 → 账号、文件、术语表、入口、服务商，不用改。
另外用底座包、`retain-pdf-core`、`retain-pdf-data`、`retain-pdf-proc`，以及 `runtime_gateway` 背后的 `retain-pdf-runner`。

## 测试怎么分

任务领域原来有 197 个测试函数（`#[test]`、`#[tokio::test]`），161 个跟着挪进包里；7 个文件里的 36 个包里放不下：

| 测试 | 为什么放不下 | 挪到哪 |
|---|---|---|
| 建任务 `creation/tests.rs`、按页额度 `page_quota_tests.rs`、平台设置 `platform_tests.rs` | 要搭整个 `AppState`；有一个还用 rust_api 装配里的 `build_jobs_facade_with_launcher` | `api_tests/jobs_creation/` |
| 查询 `query/tests.rs`、列表筛选 `list_selection_tests.rs` | 要搭整个 `AppState`（用 `api_tests::jobs_common::test_state`） | `api_tests/jobs_query_service/` |
| 事件流里 2 个、下载里 1 个"书库视图和任务视图对得上"的测试 | 要调书库的函数，书库依赖任务，任务包里引用不到 | `services/library/jobs_view_parity_tests.rs` |

测试内容不变，只改了引用：
- 原来写 `super::submit::submit_job` 这类内部路径的，改成从门面取 `crate::services::jobs::submit_job`。
- 这几个只给测试用的东西挂在 `test-fixtures` 特性下，rust_api 的 `[dev-dependencies]` 打开它：
  - 建任务的 `submit_job`、`NewJob`、`relaunch_in_place`、两个快照构建函数；
  - 查询的 `list_jobs_filtered`；
  - 列表视图的 `build_job_list_view`、`build_document_job_list_view`。
- 事件流测试、下载测试用的临时库和假渲染器（原来各自写在测试文件里的 `Fixture`）挪成包里的
  `progress/event_feed/fixture.rs`、`files/downloads/fixture.rs`，同样挂在 `test-fixtures` 下：
  - 任务包自己的测试照旧用它们；
  - 书库那 3 个测试也用它们，不用另抄一份。
  拆书库时这 3 个测试跟着书库走，书库包的 dev-dependencies 打开任务包的 `test-fixtures`。
- 原来只在 `#[cfg(test)]` 下才有的测试钩子，跨包看不到，改成 `#[cfg(any(test, feature = "test-fixtures"))]`：
  - 开发默认值的线程覆盖 `DevDefaultsGuard`；
  - 摘要缓存的读取计数 `SummaryCache::read_attempts`；
  - 事件历史的读取字节计数。
- 查过正式构建：`cargo tree -e normal,features` 里 rust_api 只打开了任务包的 `default`，没有 `test-fixtures`。

还有两处路径跟着目录深度改：
- `data/mod.rs` 在编译期 `include_str!` 读取数据登记表 `backend/contracts/job-data.v1.schema.json`。挪进包以后少了一层，
  原来的 `../` 个数会指到仓库根目录的 `contracts/` 下的同名文件。两份内容一样，本机编得过，
  但 Docker 构建的 builder 阶段只拷了 `backend/contracts/` 那份，`.github/scripts/tests` 的交付检查报了出来。已改成指回 `backend/contracts/`。
- 用量测试按 `CARGO_MANIFEST_DIR` 找契约 `token-usage.v1.schema.json`，包目录深了一层，改成 `../../contracts/`。

## 架构检查

准备阶段已经把任务的规则都改成逻辑路径，这次照计划只改了三处：
- `DOMAIN_MOUNTS["jobs"]` 指向包；
- `EXTRACTED_DOMAINS` 加上 `jobs`；
- `services/mod.rs` 接上。

另外查出并修了下面几处。

**1. 规则自检报出两条指向已挪走测试文件的路径。**
- AppState 白名单里的 `creation/tests.rs`、`page_quota_tests.rs`：测试挪到 `api_tests/` 后不在受管目录里，删掉这两条。
- `ProcessRuntimeDeps::new` 白名单里的 `creation/tests.rs`：那个文件里本来就没有这个调用，是早就过时的条目，删掉。
  单测改成"建任务目录里写了也报、`app/jobs.rs` 里不报"。

**2. 三条规则只认 `crate::` 开头的写法，包里改写包名以后会什么都不查。** 准备阶段的彩排只挪了目录、没改写路径，所以没发现。改成两种写法都认：

| 规则 | 原来只认 | 现在 |
|---|---|---|
| 模型要从门面导入（`check_service_model_facade_boundaries`） | `use crate::models::…` | 也认 `use retain_pdf_core::models::…`，任务、书库的模块照旧只许用 `models::{api,domain,request}` |
| 下载门面要薄（`check_downloads_do_not_generate_artifacts`） | `crate::storage_paths::` | `storage_paths::` |
| 快照工厂不拼命令（`check_worker_command_boundary`） | `crate::worker_command` | `worker_command::` |

每条都补了"包里写包名也报"的单测（在挪走布局下也跑一遍）。单测总数还是 124 个：补的断言加在原有用例里，另外一个用例改了名。

**3. 往真实的任务包里故意写违规，按包里现在的写法写。** 在临时拷贝里改了 11 个文件，检查报了 13 条，每种都报出来了：
- `AppState`；
- 碰 `retain_pdf_runner::job_runner`；
- 自己拼产物路径（`retain_pdf_core::storage_paths::resolve_output_pdf`）；
- `ProcessRuntimeDeps::new`；
- 模型越过门面（`retain_pdf_core::models::job`）；
- 直接读 `job.request_payload`；
- 下载层起子进程；
- 快照工厂引 `retain_pdf_data::worker_command`；
- 下载门面引 `storage_paths`；
- 任务包依赖 `retain_pdf_ai`（不允许的领域方向）；
- 自己落库建任务。

## 怎么保证行为没变

- 三份快照都没变。
- 函数体没有改动，只改了路径、可见范围、测试钩子的 `cfg`，以及上面两处跟着目录深度改的文件路径。
- 测试总数不变：
  - 拆之前 rust_api 的单测是 642 个通过、1 个忽略；
  - 现在 rust_api 482 个，加任务包 160 个通过、1 个忽略，合计一样；
  - 挪出去的 7 个文件还在 rust_api 里，只是换了位置。
