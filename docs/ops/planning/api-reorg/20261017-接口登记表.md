# 接口登记表

> 日期：2026-10-17
> 分支：`refactor/endpoint-registry`（接在 `refactor/stored-artifact-exit` 后面）
> 方案：[模块化单体拆包规划](./20261015-模块化单体拆包规划.md)第 4 节"规则交给机器守"的第 1、2 条，第 8 步

## 决定

用户 2026-10-17 定：按原规划做。
- 一个接口一条，写明方法、地址、处理函数、访问策略和一句话说明；
- 路由注册和访问控制都从这张表来；
- 接口目录从所有表自动汇总。

分两个分支做：
1. **本分支**：把路由文件改成登记表，路由注册和接口目录从表生成。访问控制还是账号包按前缀判断，但测试会核对每一条登记的访问策略和前缀判断一致。
2. **下一个分支**：访问控制改成直接查登记表，删掉账号包里按前缀判断的那套规则。

和原规划不一样的一处：原规划写"每个包有自己的 `endpoints.rs`"。处理函数都在 rust_api 的 `routes/` 里，领域包里没有 HTTP 的东西，
所以登记表放在 rust_api 的路由文件里，一个领域一张（`app/router/<领域>.rs`，任务按 9 类是 `app/router/jobs/<类>.rs`）。

## 怎么写

`backend/api/src/app/endpoints.rs` 的 `crate::endpoints!` 宏，一张表同时生成：
- `routes()`：注册进 axum 的路由；
- `ENDPOINTS`：这些接口的说明。

```rust
crate::endpoints! {
    state: AppState;
    /// 现在能做哪些操作（每个阶段能不能重试、重试的请求怎么写）
    GET "/api/v1/jobs/:job_id/actions" => actions::get_stage_actions, signed;
    GET "/api/v1/jobs/:job_id/stage-actions" => actions::get_stage_actions, signed old "/api/v1/jobs/:job_id/actions";
    /// 上传一个 PDF（不限请求体大小）
    POST "/api/v1/uploads" => uploads::upload_pdf, signed [unlimited_body];
}
```

- 一个方法一条。同一个地址的几个方法分几行写，宏里按 axum 的规矩合到一起。
- 谁能用：`public` 不需要登录、`signed` 登录就能用、`admin` 只给管理员、`closed` 对网站账号关闭。只在多用户模式下起作用。
- `///` 是一句话说明，现用地址必须写。
- 旧地址：
  - 行尾写 `old "<新地址>"`，新地址要在登记表里、方法相同，否则测试红；
  - 说明可以省，写了会在接口目录里跟在旧地址后面。
- 方括号里是附加选项，现在只有 `[unlimited_body]`：去掉请求体大小限制，上传文件用。

## 做了什么

- 27 张登记表，223 个接口：165 个现用地址、58 个旧地址。改成登记表之前，路由散在 26 个文件里：
  - 15 个领域路由文件和 9 个任务路由文件（`app/router/*.rs`、`app/router/jobs/*.rs`）；
  - `app/router.rs` 里的助手终端；
  - `routes/model_requests.rs` 里的模型调用路由。

  后两处挪成了 `app/router/terminal.rs`、`app/router/model_requests.rs`（发令牌、工作进程两张表，鉴权不同）。
- 每个现用地址补了一句话说明。任务的 9 类照[任务与文件接口整理](./20261015-任务与文件接口整理.md)的说明列，其余照处理函数写。
- `/ocr/jobs/*` 这组旧别名标成旧地址，指向对应的 `/jobs/*`。任务下的封面、缩略图，书的 `/source.pdf`、`/cover`，都指向书下面的 `/files/:name`。
- **接口目录** `docs/api/00-接口目录.md`：按路由文件分组，一行一个现用地址，写明方法、地址、谁能用、说明、旧地址、处理函数。由测试生成，不要手改。
- **接口清单快照** `docs/routes.txt` 也改成从登记表生成。223 行一行没变，只改了文件头那句"由谁生成"。

## 测试和检查

在 `api_tests/route_manifest.rs`：
- `route_manifest_matches_snapshot`：接口清单和快照一致。同时核对每条登记的谁能用，和账号包 `route_policy` 按前缀判断的结果一致。下一个分支删掉前缀判断时，这条改成只看登记表。
- `endpoint_directory_matches_registry`：接口目录和登记表一致。
- `endpoint_registry_is_complete`：
  - 现用地址都有说明；
  - 旧地址指向的新地址存在、方法相同、本身不是旧地址；
  - 同一个方法和地址只登记一次。
- `routes_are_registered_only_through_endpoint_tables`：路由文件里直接写 `.route(` 就红。加接口只能加在登记表里，不登记就没有说明，也进不了接口目录。

原来的路由源码解析（`routes_in`）和它的单测删掉了，不再需要。路径参数分类的测试照旧扫路由文件里的地址字符串，登记表里的地址都写全，不受影响。

## 行为有没有变

- 路由本身没变：同样的地址、方法、处理函数，上传接口照旧不限请求体，公开接口照旧有方法不对时的统一回复。
  全部 HTTP 测试照常通过。
- 只有一处写法上的差别：`/ocr/jobs` 原来是 `post(..).get(..).layer(不限请求体)`，限制对两个方法都去掉。
  现在只给 `POST` 去掉，`GET` 没有请求体，没有区别。
