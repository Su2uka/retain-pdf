# 书库接口的删留

> 日期：2026-10-19
> 起因：[书库接口审计](./20261019-书库接口审计.md)第三节要用户定

用户 2026-10-19 定，四项都按审计的建议：

| 事情 | 决定 |
|---|---|
| `/library/books`（书架）和 `/documents` 两套 | 留 `/documents`，书架冻结、不再加字段：<br>• `GET /library/books/:job_id` 没有调用方，直接删；<br>• 新加 `DELETE /api/v1/jobs/:job_id`，放在任务的 lifecycle 类下，OCR 任务也能删；`DELETE /library/books/:job_id` 标成旧地址 `old "/api/v1/jobs/:job_id"`；<br>• 前端改调 `GET /jobs?job_ids=` 以后，再删 `GET /library/books`。 |
| 标签残留 | 全部清掉：<br>• 后端去掉 AI `list_documents` 工具的 `tag` 参数和结果里的 `tags`，改登记表说明和文档；<br>• 前端去掉标签过滤和发送；<br>• 两边都不发了以后，书的列表和 PATCH 再拒绝不认识的字段。 |
| `POST /assets`、`GET /assets/:asset_id` | 删，连同 `assets` 表、`data/assets/` 和 `AssetConfig`。 |
| 合集 agent 工作区 | 新加 `POST /api/v1/collections/:collection_id/agent-workspace`；GET 标成旧地址，前端改用 POST 以后删掉 GET。编号校验、合集不存在返回 404、删合集时清目录照修。 |

没问用户、先不动的：
- `GET /documents/:id/agent-versions`：和 AI 那块的文档操作接口一起定。
- 同一个 PDF 重复上传多存副本（审计 C11）：改了会影响 `upload_id` 的语义，以后单独定。
