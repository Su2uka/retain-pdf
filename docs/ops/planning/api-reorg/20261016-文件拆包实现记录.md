## 做了什么

文件领域拆成第六个领域包 `retain-pdf-files`，放在 `backend/packages/retain-pdf-files`。它管这几样：
- 产物清单和打包 `artifacts`：登记表、打包、书名规则、展示；
- 按需生成的派生产物 `derived_artifacts`：线性化 PDF、预览图、双语对照 PDF、Word；
- 同一份产物同时只生成一次 `download_generation`；
- 下载文件名 `download_names`。

照样板做：
- 整个目录挪过去，`mod.rs` 改名 `lib.rs` 当门面；
- 路径改成直接写包名：
  - `retain_pdf_api_base::error`、`retain_pdf_api_base::job_loading`；
  - `retain_pdf_core::models`、`retain_pdf_core::storage_paths`；
  - `retain_pdf_data::db`；
- 门面导出的东西改成 `pub`。rust_api 用到的字段和方法也改成 `pub`：
  - `LayoutDocxOptions::dpi`、`cache_suffix`；
  - `BookImageKind::file_name`、`width_px`；
  - `DerivedArtifactDeps` 的两个字段和两个构造函数；
  - `run_supervised` 返回的 `Diagnostics` 和它的 `error`；
- rust_api 里写 `pub(crate) use retain_pdf_files as files;` 接上，任务、书库、`AppState` 里原有的 `crate::services::files::…` 一行没改；
- 加进 `EXTRACTED_DOMAINS`、工作区成员、`Dockerfile.app` 的两个阶段、合并前的 `cargo test`。

拆之前查过的依赖：
- 只用到底座包、`retain-pdf-core`、`retain-pdf-data`，不依赖别的领域，`ALLOWED_DOMAIN_DEPENDENCIES` 不用改；
- 用到的外部包：`fastrand`、`libc`、`serde_json`、`tokio`、`walkdir`、`zip`，版本和 rust_api 里的一样。

## 架构检查

文件领域是产物路径规则的主要对象，原来好几条规则直接写着 `services/files/...` 的路径。拆走以后这些路径不存在了，
不改的话规则会静悄悄地什么都不查（平台拆包那次就漏过一回）。这次逐条改到包里：

| 规则 | 原来查的 | 现在 |
|---|---|---|
| 产物路径只许出口模块拼（`check_artifact_path_ownership`） | `services/files/artifacts`、`services/files/derived_artifacts` 是出口，可以拼 | 另外扫文件包：包里只有 `src/artifacts`、`src/derived_artifacts` 能拼，下载文件名、生成去重、门面都不许。冻结名单 `KNOWN_ARTIFACT_PATH_READERS` 没变 |
| 产物边界不懂服务商原始结构（`check_artifact_boundary_layer`） | `services/files/artifacts/` 下 5 个文件不许用 `crate::ocr_provider::`、不许出现服务商原始字段名 | 改成查文件包 `src/artifacts/` 下同样的 5 个文件；包里写的是 `retain_pdf_data::ocr_provider`，两种写法都算 |
| 公共产物展示只吃视图数据（`check_shared_artifact_presentation`） | `services/files/artifacts/presentation` 不许碰任务、书库、数据库、文件系统、子进程 | 改成查文件包的 `src/artifacts/presentation`，禁止的词不变 |
| 模型要从门面导入（`check_service_model_facade_boundaries`） | `services/files/artifacts`、`derived_artifacts` 只能 `use crate::models::{api,domain,request}` | 删掉这几条：包里写 `retain_pdf_core::models`，这条规则只认 `crate::models`，前几个包也是这么处理的 |
| 下载门面要薄（`check_downloads_do_not_generate_artifacts`） | `downloads.rs` 不许写 `crate::services::files::derived_artifacts` | 删掉这个词：子模块在别的包里是私有的，编译器已经挡住了 |

改完以后：
- 往真实代码里故意写违规：
  - 文件包 `download_names.rs` 拼产物路径，报了；
  - 写在 `derived_artifacts/word.rs` 里不报，它是出口；
  - `presentation.rs` 引数据库，报了；
  - `registry.rs` 用 `ocr_provider` 和服务商原始字段名，报了。
- 说明新路径扫到的是真的文件。
- 单测从 61 个变成 62 个：
  - 新加一个"文件包里出口以外的模块不许拼路径"；
  - 原有用例的路径改到临时目录里的文件包；
  - 单测工具 `check_sources` 支持 `packages/` 开头的键，写进临时目录里的领域包。

注意：违规写在文件末尾的 `#[cfg(test)]` 后面不算。检查会去掉测试代码，这是原来就有的行为。

## 前端

- 前端没有测试读这个领域的源文件，只有 3 处注释写着 `download_names.rs` 的旧路径。
- 它的新位置是 `backend/packages/retain-pdf-files/src/download_names.rs`，已经告诉前端会话。
- 上一次推送有一个前端测试红了，原因是它直接读了被挪走的后端文件。从这次起，挪文件前先在 `frontend/` 里搜一遍路径。

## 怎么保证行为没变

- 三份快照都没变；
- 函数体没有改动，只改了路径和可见范围；
- 测试总数不变（见开发记录）。
