> 日期：2026-10-19

## 怎么做的

- 接任务那块之后，按块细化接口，书库是第二块。
- 分三组，每组一个子代理，只读代码，没跑测试。
- 每个接口过同一份检查单：
  - 地址和命名；
  - 返回结构；
  - 报错，对照已定的四条规矩（[任务接口的规矩和删留](./20261019-任务接口规矩和删留.md)）；
  - 契约；
  - 文档；
  - 调用方；
  - 明显的正确性问题。
- 标"已核对"的我自己对着代码看过。

一共 42 条：高 0、中 21、低 21。下面按"该怎么处理"重新归类，不按组。

## 一、确定是错的，直接修（对前端没影响）

## 二、按已定的规矩改（对前端只增不改）

- **分页**：`/documents`、`/library/books`、`/search`、元数据建议列表、Agent 版本列表都把 `limit` 静默夹到上限，不回显 `limit`，没有 `has_more`。照[分页约定](../../../api/00-约定/03-分页.md)改（A4、C8）。`/documents/:id/jobs` 已合规，只剩三个小缝（B14）。
- **不认识的字段 400**：书和合集的请求体、查询参数，元数据建议的请求体都静默忽略不认识的字段（A7、C7）。合集 PATCH 的 `parent_id` 尤其误导：传了不报错，也不生效。要先等前端和 AI 工具不再发标签（第三节 2）。
- **书不存在时用量给 200**：`/documents/:id/usage` 在书不存在时回 200 空汇总。规矩是任务或书不存在一律 404，不带 reason（B7）。

## 四、契约和返回结构

- **没有契约**（A9、B5）：书、合集、搜索、阅读入口、翻译覆盖、书的文件清单都没有 schema，前端类型手写或是 `any`。`library-books.v1` 里还挂着已删的 `batch-delete`。建议新增 `library-documents.v1`，Rust 测试照 `job_view_contract.rs` 钉键集合。
- **返回结构**（A8、B15、C3）：
  - 同一类东西有几种写法，还有几个死字段；
  - 删除结果里带服务器绝对路径；字体列表也返回绝对路径；
  - 翻译覆盖里的 `jobs[]` 是第三种任务摘要；
  - apply 返回的书比 PATCH 少三个链接。
- **`GET /documents?job_id=` 是塞在列表接口里的另一个接口**（A10）：保留，文档写清"带 `job_id` 时其余参数无效"。
- **页数来源不一致**（B8）：翻译覆盖和阅读入口用的页数来源不一样。
