# 旧地址用量报表

> 日期：2026-10-17
> 分支：`ops/route-usage-report`
> 工具：`ops/development/route_usage_report.py`

## 为什么

接口整理后，很多接口有了新地址，旧地址按约定先保留（接口目录里"旧地址"那一列）。
现在登记表里有 58 个旧地址。删之前要知道有没有人还在调，而静态搜代码判不了：
前端的地址是拼出来的，源码里搜不到完整的 URL；`internal/agent/operations` 就因此被误判过一次。

应用已经在按**路由模板**给每个接口计数（`backend/api/src/app/route_usage.rs`），
落在 `<data_root>/diagnostics/route-usage.json`。这个脚本把计数和登记表对起来，出一份报表。

## 怎么跑

在仓库根：

```bash
python3 ops/development/route_usage_report.py                     # 自动找 data/**/diagnostics/route-usage.json
python3 ops/development/route_usage_report.py data/diagnostics/route-usage.json   # 指定文件，可多个
python3 ops/development/route_usage_report.py --json              # 机器可读
```

只用标准库，不依赖 cargo，不连运行中的应用。登记表是用正则直接读
`backend/api/src/app/router/` 下的 `crate::endpoints!` 表；测试里核对过解析出来的接口和
`backend/api/docs/routes.txt` 一一对应，登记表的写法一变这条测试会先红。

报表内容：

- 每个用量文件的 `since`、`updated_at`、路由条数、总调用数；
- 每个旧地址（方法、路径、新地址、所在路由文件）在每个文件里的调用次数，以及它新地址的调用次数；
- "还有调用"（按合计从多到少）和"零调用"两段；
- "用量里有、登记表里没有的路由"单列：多半是已经删掉或改过名的地址留下的旧数据。

几处约定：

- 单机、多用户、`single-check` 各有各的数据目录和用量文件，所以按文件分列，不合并；
- axum 对 GET 路由自动接 HEAD，用量里记成 `HEAD /路径`，报表并入同路径的 GET；
- 旧地址的新地址只写了路径、没写方法时（例如 `POST /ocr/jobs` 的新地址是 `/jobs`），
  新地址的调用数取这个路径上登记过的各个方法之和。

## 怎么清零

```bash
python3 ops/development/route_usage_report.py --reset data/diagnostics/route-usage.json          # 只打印会做什么
python3 ops/development/route_usage_report.py --reset data/diagnostics/route-usage.json --yes    # 真的执行
```

执行 = 把原文件改存为同目录的 `route-usage.<UTC 时间戳>.json`，再写一个 `since` 为现在、`routes` 为空的新文件。

**必须先停应用。** `route_usage.rs` 是这样写文件的：启动时读一次，之后计数在内存里累加；
每 60 秒把内存里的整份计数写回文件，关机时不再补写。应用开着清零，下一分钟内存里的旧计数就把新文件盖回去了。
脚本会看 `updated_at`：不到 120 秒前还在更新就拒绝，确实停了再加 `--even-if-running`。
顺带：关机时最后不到一分钟的计数会丢，对"有没有人在用"这个问题没有影响。

## 约定的流程

1. 停应用，各数据目录的用量文件清零（`--reset … --yes`），再启动；
2. 正常用几天（覆盖前端各个页面、AI 服务、桌面端的常见操作）；
3. 跑报表，看"还有调用"和"零调用"；
4. 把"零调用"清单发给前端确认：前端的地址是拼出来的，零调用只说明这段时间没人调，不等于没有调用方，
   前端能认出来的偶发路径要补回去；
5. 确认后再删：登记表里的那一行、处理函数、文档和三份接口快照一起改，同一个分支。

"还有调用"的旧地址不删，先让前端改成新地址，换完再清零重测一轮。

## 样本的局限

- 几天的样本只覆盖这几天做过的事，月度才用一次的功能可能零调用，所以清单要发前端看，不是跑完就删；
- 只计登记过的路由模板；没匹配到路由的请求（404）不计；
- 计数不分调用方，AI 服务、桌面端、浏览器的调用混在一起。
