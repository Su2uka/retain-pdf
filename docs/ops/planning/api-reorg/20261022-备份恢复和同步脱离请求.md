2026-10-22，分支 `fix/backup-sync-detached`。修 [设置与平台接口审计](./20261022-设置与平台接口审计.md) 一-3、4、5、7（`sync/test`）、
12（同步、备份）和二的备份同步部分；明细是 [C 备份、同步、上传与内部](./20261022-设置与平台接口审计明细/C-备份同步上传与内部.md) 第 1～9 条、第 13 条的备份同步部分。

## 做了什么

| 明细 | 改法 |
|---|---|
| C1 请求断开后锁先放、活还在跑 | 照上传（`retainpdf-ingest` `uploads/service.rs`）的做法：恢复、立即/自动备份、立即同步、改同步设置整段（拿锁 → 阻塞活 → 放锁、置回 `running`、恢复后的钩子）放进 `tokio::spawn` 的任务，请求只等结果（平台包 `detached.rs`）。`running` 用 drop 守卫置回。「停住同步」同时拿同步锁和设置锁 |
| C1 顺带 | `GET /backups` 加 `last_restore`（最近一次恢复，成功/失败、`safety_backup`、`reason`、`error`）。只在内存：恢复会换掉数据库，记在库里会被换掉；重启后为 `null` 可以接受 |
| C2 换库前没再查 | `Db::restore_checked` 在换库前用同一个连接再查一次 `restore_blockers`，有就 `RestoreRefusal::Blocked` → 409 `restore_blocked`，刚存的恢复前备份删掉 |
| C3 换库后几步不原子 | 换库是最后一步：在解开的临时副本上 `apply_schema`，再一个事务里 `sync_after_restore`（写回恢复前的同步设置、重置记账）和清 pid，然后 `Backup::step(-1)` 一步换进去。之后只剩 `PRAGMA journal_mode=WAL; foreign_keys=ON` 这一保险，失败只记日志。所以不用「失败时用安全备份恢复回去」，`500` 时库没变；500 的 `details` 没加 `safety_backup`（`AppError::Internal` 只带 `error_id`，加一个变体要动底座包），改由 `last_restore.safety_backup` 告诉调用方 |
| C3 恢复期间 `PUT /sync` 被盖回 | 改设置拿设置锁，恢复期间（停住同步时）拿着同一把锁：恢复期间的 `PUT /sync` 等恢复结束才写 |
| C4 WebDAV 密码跟着备份走 | `write_backup` 在 `VACUUM INTO` 出的副本上 `secure_delete` 删掉 `webdav_password` 再压缩；副本和 `.db.gz` 先建成 `0600`（`VACUUM INTO` 接受空文件）。恢复保留恢复前的 `sync_state`，不受影响。旧备份里的密码不清（只在文档里提醒） |
| C5 `sync/test` 超时 | `WebDavBackend::for_probe`：每个请求（含连接）10 秒、不重试；探针改成直接 PUT（409 才建目录），同步文件夹已在时 5 个请求减到 3 个；`SyncService::test` 外层 60 秒。前端 `apiFetch` 不设超时，所以没有「比前端短」的约束，按「几秒到几十秒给结论」定。正式同步的客户端不动 |
| C6 异步里阻塞 | `BackupService::status`、`delete`、自动备份查列表，`SyncService::status`、`update` 放进阻塞线程；`run_once` 的开关/目标判断挪进阻塞线程 |
| C7 409 reason | `restore_blocked`、`backup_damaged`、`backup_newer`（后两个 400 → 409）、`sync_disabled`、`sync_not_configured`（措辞分开）。前端、CLI 都只显示 `message`，不看状态码 |
| C8 失败的恢复挤掉恢复前备份 | 拆出 `Db::check_backup`（解压、完整性、版本），检查不过直接拒绝，不存恢复前备份；CLI 离线恢复同样 |
| C9 `PUT /sync` 写一半、不认识的字段 | `SyncControl::update` 全部校验完（开启时目标齐不齐按 `target(Some(input))` 叠加算）才写，用新的 `Db::sync_state_set_many` 一个事务写；只在成功时唤醒同步；`SyncSettingsInput` 加 `deny_unknown_fields`（`PUT /sync` 和 `sync/test` 都用它） |
| C13 | `03-分页.md` 写明 `/backups` 的 `items`、`/sync` 的 `pending`、`peers` 不分页 |

## 没做

- **「恢复中」标记、建任务入口 409**（C2 更彻底的做法）：要动任务包的 `submit_job`、AI 改文档入口。现在换库前再查一次，
  窗口缩到「查完到一步换库」之间（同一个阻塞线程里，毫秒级），没有彻底关上；上传正在发布（`publish_upload`）、AI 对话正在写消息
  也不在 `restore_blockers` 里。单独开分支。
- **`sync/run` 已有一轮在跑时直接回当前状态**（C9 第三点）：是行为变化，要先和前端确认，这次照旧排队（请求断开也不会再放锁）。
- **开着同步时把同步位置清空**：照旧允许（之后 `sync/run` 回 `sync_not_configured`），只有请求里带 `enabled: true` 时才查目标齐不齐。
- **WebDAV 密码改存凭据库**（C4 长远做法）：这次只让它不进备份。
- **`/health`、模型执行器的阻塞**（C6 其余部分）：不在这个分支（`/health`、执行器分给别的分支或以后）。
- **契约**：备份、同步还没有 schema，前端类型手写（C13 建议暂不加）。
