# 任务与文件接口整理方案（草案）

> 日期：2026-10-15
> 相关：[模块化单体拆包规划](./20261015-模块化单体拆包规划.md)
> 状态：**方案已定**（第 7 节的待定项 2026-10-15 全部确定）。文件出口（第 3 节）已实现，
> 见 `refactor/api-files` 分支；其余各类还没动。
> 更正（2026-10-15 实现时）：封面、缩略图、预览图生成的是 JPEG，文件名用 `.jpg`，不是 `.png`。
> 范围：`/jobs` 下的 50 个接口、书（document）的文件接口，以及它们的旧别名
> （`/ocr/jobs/*`、`/library/books/:id/cover|thumbnail`）。其他接口见文末附录，下一轮再整理。
> 调用次数取自多用户开发环境的访问统计（2026-10-10 ~ 2026-10-15，基本是一个人在测），
> **0 次不等于没人用**：后端返回的链接、AI 服务、命令行、桌面版都可能调用，删旧地址前逐个核实。

## 1. 规则

1. **按"调用方想问什么"分 9 类**，每类一个固定前缀，`/jobs/:id/` 后面的第一段只能是这 9 个之一
   （接口清单测试强制）。
2. **路径里只有名词**，不出现 download、preview 这类动作；操作类统一放在 `actions/` 下。
3. **东西属于谁就挂在谁下面**：书本身的东西（原文、封面、缩略图、原文页）挂在 `/documents/:id`；
   这一次加工产出的东西挂在 `/jobs/:id`。
4. **文件名一律是"内容.格式"**，带扩展名，同类放子目录；变体用查询参数（`?dpi=150`），
   不另开地址；在浏览器里看还是下载用 `?download=1` 区分。
5. **一律小写加连字符**（`side-by-side.pdf`），不再出现下划线写法（`normalized_document_json`）。

## 4. 旧地址怎么处理

1. 新地址上线后，旧地址先保留，内部转发到同一处代码，在接口清单里标成"旧"。
2. 后端在任务详情、书籍详情里返回的链接（`build_artifact_links`、操作链接等）先换成新地址。
   前端大部分下载是照着这些链接去请求的，会自动跟上；前端自己拼地址的地方
   （阅读页、Markdown、画板、产物列表）这次一起改。AI 服务、命令行一起改。
3. 用访问统计和代码搜索确认旧地址没人调用以后再删。
4. 旧别名一并处理：
   - `/ocr/jobs/*`（10 个，多用户下已关闭）：转发到对应的 `/jobs/*` 新地址，确认后删除。
   - `/library/books/:id/cover|thumbnail`：转发到书的 `cover.jpg`、`thumbnail.jpg`。

## 5. 权限变化（唯一的行为变化）

`internal/` 在多用户模式下只给管理员。受影响的地方：

- 前端任务详情页的"产物清单"会列出全部中间产物：网站账号以后看不到这些，管理员不变。
- 前端书籍详情页的资源列表里有"规范化文档""规范化报告"两项下载：网站账号以后不显示。
- AI 服务直接读磁盘上的任务目录（`retainpdf_ai/blocks.py`），不走这些接口，**不受影响**。

单机模式不受影响。

## 6. 代码怎么放

路由注册、处理函数、业务逻辑三层都按这 9 类分文件，名字一致：

```
routes/jobs/{lifecycle,actions,progress,files,reports,reader,translations,data,ai}.rs
services/jobs/{lifecycle,actions,progress,files,reports,reader,translations,data,ai}/
```

所有文件接口内部都落到同一个函数 `open(任务, 文件名)`：按名字查产物登记表；
按需生成的产物交给现有的生成函数，同一个产物被同时请求时只生成一次。
`services/artifacts` 以外的代码不再直接调用 `resolve_output_pdf` 这类路径函数，检查脚本强制。

## 7. 待定项的决定

2026-10-15 全部确定：

- [x] **"报告"和"数据"先不合并。** 报告是固定格式、前端按字段直接读；数据是通用查询。
      等报告都能用"数据表"表达时再合。
- [x] **只留 `internal/ocr-provider/result.json`，去掉 `internal/layout.json`。** 本地 133 个同时有
      这两项的任务，路径全部相同（`ocr/paddle_result.json`）。任务记录里的 `layout_json` 字段内部照用，
      只是文件列表里不再出现两次。本地全是 Paddle 的任务，MinerU 的情况动手时再核实。
- [x] **没关联到书的任务：内部保留退路，对外不保留地址。** 本地 140 个任务全部已关联到书；
      桌面版老数据查不到，所以内部保留"书找不到就按任务找原文"，对外只有 `/documents/:id/files/…`。
- [x] **"能做什么"和"续跑计划"不合并，只改地址。** 两个接口前端分别在调（近 5 天 206 次、68 次），
      这次只统一地址，不改返回格式。
