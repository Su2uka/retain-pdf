# 任务接口分类实现记录

> 日期：2026-10-16
> 分支：`refactor/api-categories`
> 方案：[任务与文件接口整理](./20261015-任务与文件接口整理.md) 第 2 节（9 类）、第 6 节（代码怎么放）

## 为什么补这一步

[拆包规划](./20261015-模块化单体拆包规划.md)的步骤表里，第 3 步只排了"文件"这一类。
另外 8 类（操作、进度、报告、阅读、译文、AI；任务和数据本来就对）的新地址一直没排进去。
2026-10-16 用户问到才发现，记为第 4.5 步补上。

## 做了什么

**新地址**：一共 29 个接口（27 条路径），清单在 [任务接口分类](../../api/01-任务/04-任务接口分类.md)。
- 每个新地址和它的旧地址指向同一个处理函数，返回完全一样。
- 旧地址一个没删。
- 接口清单快照 `routes.txt` 只多了 29 行：`166 条路径，194 个接口` → `193 条路径，223 个接口`。

**路由按 9 类分文件**：
- `app/router/jobs.rs` 拆成 `app/router/jobs/{lifecycle,actions,progress,files,reports,reader,translations,data,ai}.rs`。
  每个新地址下面紧跟着它的旧地址，行尾标 `// 旧地址`。
- 单个任务的用量 `/usage` 原来注册在备份的路由文件里，现在挪进 `reports`。

**处理函数按 9 类分文件**，`routes/jobs/` 下的文件名和路由一一对应：

| 现在 | 原来 |
|---|---|
| `lifecycle.rs` | `create.rs` + `query/read.rs` 里的列表和详情 |
| `actions.rs` | `control.rs` + `query/actions.rs` + `json_response/actions.rs` + `query/diagnostics.rs` 里的续跑计划 |
| `progress.rs` | `query/live_translation.rs` + `query/read.rs` 里的事件 |
| `files.rs` | `files.rs` + `download.rs` + `query/read.rs` 里的产物清单 |
| `reports.rs` | `routes/quality.rs` + `translation_debug.rs` 里的几份报告 + `query/diagnostics.rs` 里的失败原因 + `token_usage.rs` 里单个任务的用量 |
| `reader.rs` | `query/reader.rs` + `download.rs` 里的 Markdown 文档 |
| `translations.rs` | `translation_debug.rs` 里的条目 + `json_response/translation_debug.rs` |
| `data.rs` | `routes/job_data.rs` |
| `ai.rs` | `download.rs` 里的阅读路径、概念图、画板 |

`json_response/` 和 `query/` 两层中间目录没有了。函数体一行没改，只是换了文件。

**新旧地址返回一样的测试**：`api_tests/job_categories.rs`。
- 对同一个任务，把 23 对新旧地址各请求一次，比较状态码、类型和响应体。
- POST 只发一定会被拒的请求，不会改任务状态。
- 新地址要是漏注册、挂错处理函数，或者路径参数没归类、被多用户中间件拦下，这个测试都会报错。

**检查和测试跟着改**：
- `check_architecture.py` 按新文件名改了白名单。
- "只读接口只能用只读依赖"这条规则改成按类写：
  - 只读的类：`files`、`reports`、`reader`、`data`、`ai`；
  - 混着读写的类：`lifecycle`、`actions`、`progress`、`translations`。它们只有列出来的写操作能拿完整的任务门面。
- 接口清单快照和路径参数分类的测试都直接读路由源码。原来只读 `app/router/` 这一层，现在共用 `test_support::routes::router_source_files()`，连子目录一起读。

**后端自己的调用方换成了新地址**：
- AI 助手用的命令行 `retainpdf-agent`：`reports/translation-qa`、`reports/refine`、`reports/layout-fit`、
  `translations/:item_id`、`actions/retry-stage`。
- AI 助手的权限表 `services/agent_capabilities.rs` 新旧地址都认，同一档权限，老版本的命令行照样能用。
  权限没有变宽：`/reports/usage`、`/reports/failure`、`/actions/cancel`、`/translations/:id/replay` 照旧拒绝，加了测试。
- 流水线调试脚本 `devtools/translation_debug_api.py`，以及翻译、promptfoo 的说明文档。

## 和方案不一样的地方

- 译文条目的路径参数叫 `:item_id`，不是方案表里写的 `:item`。和旧地址一致，多用户模式下的参数归类不用另加。
- 边翻边看单页是 `/progress/pages/:page`。处理函数照旧按位置取参数，含义和旧地址的 `:page_idx` 一样。

## 没动的

- 任务详情、操作列表返回里的 `links`、`actions` 还是旧地址，返回字段一个没改。
- `/ocr/jobs/…` 这组旧别名原样保留。
- 契约文件（`contracts/*.schema.json`）的说明里写的还是旧地址，契约版本没动。
- `services/jobs/` 按 9 类分目录（方案第 6 节的第三层）这次没做。它和第 5 步拆依赖环搅在一起，放到那一步。
