# 服务商拆包实现记录

> 日期：2026-10-16
> 分支：`refactor/crate-providers`（接在 `refactor/crate-platform` 后面）
> 方案：[术语表拆包实现记录](./20261016-术语表拆包实现记录.md)里的"拆一个领域包的样板"；
> 顺序见[平台拆包实现记录](./20261016-平台拆包实现记录.md)，服务商排第一

## 做了什么

服务商领域拆成第三个领域包 `retain-pdf-providers`，放在 `backend/packages/retain-pdf-providers`，管这几样：
- 凭据库 `credentials`；
- 模型调用 `model_executor`、`model_requests_api`；
- 服务商连通性和额度探测 `provider_probe`、`provider_api`。

照样板做：
- 整个目录挪过去，`mod.rs` 改名 `lib.rs` 当门面；
- 路径改成直接写包名；
- 门面导出的东西改成 `pub`，只在包里用的照旧 `pub(crate)`；
- rust_api 里写 `pub(crate) use retain_pdf_providers as providers;` 接上，
  路由、任务领域里写的 `crate::services::providers::…` 一行没改；
- 加进 `EXTRACTED_DOMAINS`、工作区成员、`Dockerfile.app` 的两个阶段、合并前的 `cargo test`。

拆之前查过的依赖：
- 规划里记着服务商用了 `crate::app` 2 处，查下来都在测试里，正式代码没有；
- 正式代码只用到底座包、`retain-pdf-core`、`retain-pdf-data`。`ocr_provider` 本来就在 `retain-pdf-data`，
  rust_api 里只是转出口。

## 测试怎么分

模型执行器原来有 24 个测试，其中 5 个包里放不下：

| 测试 | 为什么放不下 |
|---|---|
| 提交时校验执行连接、能往返且不带密钥 | 调的是任务领域的 `validate_translation_credentials` |
| 执行连接只认 `/chat/completions` | 同上 |
| 恢复视图保留回执、挡住旧式恢复 | 调的是任务领域的 `load_translation_request_recovery` |
| 真的起 Python 工作进程，只用本地凭证 | 要搭整个 `AppState`、起整个应用 |
| 内部模型接口分开启动方和工作进程的权限 | 同上 |

这 5 个挪到 rust_api 的 `api_tests/model_executor.rs`，测试内容不变：
- 原来直接读执行器私有的 `db` 字段，现在测试自己留一份同一个数据库的句柄；
- 测试名里还带 `model_executor`，CLAUDE.md 里 `--test-threads=1` 的过滤照样能选中它们。

剩下 19 个留在包里。凭据库和探测的 40 个测试本来就只用数据库和本地起的假服务，跟着挪进包里，一行没改。

## 架构检查

- `EXTRACTED_DOMAINS` 加上 `providers`。
- 删掉这些现在由编译器保证的规则条目：
  - "外面不许点进 `credentials::service`"：凭据库的子模块在别的包里，本来就是私有的；
  - "模型要从 `models::api` 等门面导入"里的 `providers/credentials`、`providers/provider_probe.rs`：
    拆出去的包直接依赖 `retain-pdf-core`。
- **顺带补上平台拆包漏删的两条**：字体（`platform/fonts`）在这两条规则里的条目。平台拆走以后，这两条扫的目录已经不存在，
  规则什么都没查，单测还是拿临时目录测的，所以一直是绿的。对应的单测用例一起删掉。

## 怎么保证行为没变

- 三份快照都没变；
- 函数体没有改动，只改了路径和可见范围；
- 测试总数不变，都是 777 个：rust_api 从 777 个变成 718 个，服务商包正好是少掉的 59 个
  （执行器 19 个，凭据库和探测 40 个）。另外 5 个执行器测试还在 rust_api 里，只是换到了 `api_tests`。
