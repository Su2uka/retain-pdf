# 设置与平台接口的删留

> 日期：2026-10-22
> 起因：[设置与平台接口审计](./20261022-设置与平台接口审计.md)第三节要用户定

用户 2026-10-22 定，四项都按审计的建议：

| 事情 | 决定 |
|---|---|
| 重跑、阶段重试时的术语表 | **用现在的表**，加上用户当时内联的条目：<br>• 任务请求里另存真正的内联条目（只增 `translation.glossary_inline_entries`），重跑先换回它再解析；<br>• 老任务没有这个字段时按旧行为；<br>• 表已删时重跑 409 `glossary_missing`。 |
| 术语表 PUT 抹掉界面不显示的字段 | • 后端：请求里没出现的顶层字段保留原值，`name`、`entries` 仍必填；<br>• 前端：编辑行原样带回词条的 `context`；<br>• `enabled=false` 的表建任务时 400，列表加 `?enabled=true` 给下拉用。 |
| 没有调用方的接口 | • 删 `POST /api/v1/glossaries/import`、`POST /api/v1/internal/model/jobs/:job_id/capability`；<br>• `GET /api/v1/providers/ocr` 留着，补契约，"只能服务器定"的选项不再列默认值；<br>• 凭据 5 个接口留着，文档补"建任务导入的副本什么时候清"，`PUT` 不许改 `kind`。 |
| 单机模式 CORS 全放开 | 收紧，单独开一项：先查桌面壳、`file://`、开发栈各用什么来源，和前端核对，再把单机 CORS 收到本机页面和桌面壳。 |

没问用户、按审计建议做的：
- 术语去重的键改成"精确匹配区分大小写 + `context`"，`parse-csv` 回包只增 `duplicate_count`（审计第三节 3）。
- CSV 粘贴框只改前端占位符，后端默认列序不变；后端报错带行号（审计第三节 4）。
