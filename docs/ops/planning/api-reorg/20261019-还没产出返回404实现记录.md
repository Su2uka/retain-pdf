# 「还没产出」返回 404 not_ready 的实现记录

> 日期：2026-10-19
> 分支：`fix/not-ready-404`
> 规矩出处：[任务接口的规矩和删留](./20261019-任务接口规矩和删留.md) 第 2 条；问题出处：[任务接口审计](./20261018-任务接口审计.md) 第二节第 2 条（明细 C3、D2）。
> 写进约定的位置：[`docs/api/00-约定/02-认证与错误.md`](../../../api/00-约定/02-认证与错误.md#还没产出404)

## 做法

- 底座包加 `AppError::not_ready(名字)`：`404`，`error.details.reason = "not_ready"`，`message = "<名字> not ready"`；
  `is_not_ready()` 给列表类接口接住它退回空列表。任务不存在照旧走 `load_supported_job` 的普通 `404`，不带 `reason`。
- `<名字>` 用对外的名字：文件出口用地址里的文件名（`translated.pdf`、`ocr.md`、`all.zip`、`internal/` 下的文件名），
  报告用地址里的报告名（`refine report`、`layout-fit report`……）。缺的是输入时写缺的那个（对照 PDF 缺原文就是 `source.pdf not ready`）。
  文案里不再带任务编号，地址里已经有。

## 改前改后

| 接口 | 情况 | 改前 | 改后 |
|---|---|---|---|
| `files/output/translated.pdf`、`pages/N.jpg` | 没有译文 PDF | 404 `pdf not ready: <id>` / `translated pdf not ready: <id>` | 404 not_ready `translated.pdf not ready` |
| `files/output/side-by-side.pdf`、`translated.docx` | 缺原文 / 译文 / 输出目录 | 404 `source pdf not ready: <id>` 等 | 404 not_ready `source.pdf` / `translated.pdf` / `translated.docx not ready` |
| `files/output/ocr.md`、`ocr.zip` | 没有 Markdown | 404 `markdown not found: <id>` / `markdown not ready` / `markdown bundle not found` | 404 not_ready `ocr.md not ready`（打包没登记 `ocr.zip not ready`） |
| `files/output/ocr/images/…` | 没有图片目录 | 404 `markdown images not found` | 404 not_ready `ocr/images not ready`；目录在、图不在照旧普通 404 |
| `files/output/all.zip` | 任务没成功 | **409** `job is not finished successfully` | 404 not_ready `all.zip not ready` |
| `files/internal/<name>` | 还没登记 / 还没就绪 | 404 `artifact not found: <id>/<key>` / `artifact not ready: …` | 404 not_ready `<name> not ready` |
| `reader/markdown` | 没有 Markdown | 404 `markdown not found` | 404 not_ready `markdown not ready` |
| `reports/translation`、`translation-qa`、`layout-fit`、`refine` | 没有报告文件 | 404 `… not found: <id>` | 404 not_ready `translation report` / `translation-qa report` / `layout-fit report` / `refine report not ready` |
| `translations/{item}`、`…/revisions`、`PATCH`、`replay` | 没有翻译清单 | 404 `translation manifest not found` / `job root not found` | 404 not_ready `translation manifest not ready` |
| `translations`（列表） | 没有翻译清单 | **404** `translation manifest not found` | **200** 空列表 |
| `reports/quality`、`quality/items` | 任务还没有输出目录（排队） | **404** `job has no output directory` | **200**，各段 null / 空清单 |
| `data`、`data/{dataset}` | 任务还没有输出目录（排队） | **404** `job has no output directory` | **200**，`available: false` |

没动的摘要类（本来就是 200 + 空值）：`reports/usage`、`reports/failure`、`files`、`reader/regions`、`reader/metadata`、`ai/board`。

## 有取舍的地方

1. **书的原文不在磁盘上仍是普通 404，不带 `not_ready`**（`/documents/:id/files/…`、`/documents/:id/reading`）。
   书的原文随上传就有，不在就是丢了；带 `not_ready` 会让客户端以为等一会儿就有，一直轮询。
2. **边翻边看（`progress/layout`、`progress/pages/:page`）不动**。`progress/layout` 没就绪是 409 `LIVE_TRANSLATION_LAYOUT_NOT_READY`，
   和这条规矩（404）不一致；但前端按这两个 `error.code` 决定要不要重试，这里只记下，不改。要统一的话另开分支，先和前端定。
3. **名字写错仍是普通 404**：没有这个文件名、数据集、条目、页码、画板文件——那是"没有"，不是"还没好"。
4. **译文列表改成 200 空列表**：规矩里列表归摘要类。前端 `fetchTranslationItems` 本来就把 404 当空列表，200 空列表走同一个结果。
5. 状态码只改了三处（`all.zip` 409→404；译文列表、质量/取数在排队任务上 404→200）。其余原来就是 404，只是 `details` 多了
   `reason`、`message` 换了措辞。前端没有按这些英文文案判断的地方（`git grep` 核对过）。

## 阅读器碰到的地址

阅读器打开整本书（路由里只有文档）时，加载任务资源拿到 404 会当成"任务已经没了"退回原文
（`frontend/packages/reader/src/hooks/reader-session/session-load-plan.ts` 的 `isStaleDocumentJobFailure`）。
这次没有把阅读器会碰到的任何地址从非 404 改成 404：

| 地址 | 改前 | 改后 | reason |
|---|---|---|---|
| `GET /jobs/:id` | 404（任务不存在） | 不变 | 无 |
| `GET /jobs/:id/files` | 200 | 不变 | — |
| `GET /jobs/:id/reader/regions` | 200 | 不变 | — |
| `GET /jobs/:id/reader/metadata` | 200 | 不变 | — |
| `GET /jobs/:id/reader/markdown` | 404 | 404 | 没产出时 `not_ready`；任务不存在无 |
| `GET /jobs/:id/files/output/ocr.md` | 404 | 404 | 同上 |
| `GET /jobs/:id/files/output/ocr/images/…` | 404 | 404 | 图片目录没有时 `not_ready`；图不在、任务不存在无 |
| `GET /jobs/:id/files/output/translated.pdf` | 404 | 404 | 没产出时 `not_ready`；任务不存在无 |
| `GET /documents/:id/files/source.pdf` | 404 | 不变 | 无 |
| `GET /documents/:id/reading` | 200 / 404 | 不变 | 无 |
| `GET /jobs/:id/progress/layout` | 409 `LIVE_TRANSLATION_LAYOUT_NOT_READY` | 不变 | — |
| `GET /jobs/:id/progress/pages/:page` | 404 `LIVE_TRANSLATION_PAGE_NOT_COMMITTED` | 不变 | — |
| `GET /jobs/:id/ai/board`、`ai/board/:name` | 200 / 404 | 不变 | 无 |

前端改 `isStaleDocumentJobFailure`：404 且 `error.details.reason === "not_ready"` 时不走"任务丢失"。
