## 做了什么

账号领域拆成第四个领域包 `retain-pdf-accounts`，放在 `backend/packages/retain-pdf-accounts`。它管这几样：
- 登录、会话；
- 访问控制 `access`；
- 管理后台、邀请码；
- 页额度、平台设置。

多用户模式 2026-10-16 起不再维护，这次只挪位置，不改逻辑。

照样板做：
- 整个目录挪过去，`mod.rs` 改名 `lib.rs` 当门面；
- 路径改成直接写包名，用服务商的地方写 `retain_pdf_providers::…`；
- 门面导出的东西改成 `pub`；原来 `pub(super)`（对整个 services 可见）的改成 `pub(crate)`；
- rust_api 里写 `pub(crate) use retain_pdf_accounts as accounts;` 接上，原有的 35 处 `crate::services::accounts::…` 一行没改；
- 加进 `EXTRACTED_DOMAINS`、工作区成员、`Dockerfile.app` 的两个阶段、合并前的 `cargo test`。

## 和前几个不一样的地方

**1. 第一个依赖别的领域包的包。**
- 账号用服务商的凭据库（平台设置里存、测连通性），所以 `retain-pdf-accounts` 依赖 `retain-pdf-providers`。
- 架构检查原来只在 `services/` 下找 `crate::services::<领域>` 来算领域之间的依赖。拆出去的包写的是包名，原来那套找不到，
  检查报 "账号 → 服务商这条登记了却没人用"。
- 现在 `check_domain_dependency_direction` 也扫拆出去的包，把包里写的 `retain_pdf_<领域>` 算作一条依赖（不算测试和注释），
  照样对照 `ALLOWED_DOMAIN_DEPENDENCIES`。配了 2 个单测，单测一共 64 个。

**2. `Principal` 的提取器跟着挪进包里。**
- 处理函数参数里直接写 `principal: Principal`，靠的是 `auth.rs` 里给它实现的 axum `FromRequestParts`。
- `Principal` 挪进账号包以后，在 rust_api 里给外部类型实现外部 trait 违反孤儿规则，编译不过。
- 这个实现就挪到账号包里，紧跟在 `impl Principal` 后面，代码没改。

**3. 生成盐的随机源要自己声明。**
- 密码哈希的盐用 `OsRng`，它要 `rand_core` 的 `getrandom` 特性。
- 在 rust_api 里，这个特性是另一个依赖（`tokio-tungstenite` → `rand`）碰巧打开的。账号包单独编译时没有它，编译不过。
- 现在在账号包的 `Cargo.toml` 里明确写上。

**4. 只给测试用的导出改成照常导出。**
- 原来 `#[cfg(test)]` 导出给 rust_api 测试用的有两组：
  - 访问策略 `route_policy`、`RoutePolicy`：接口清单快照要用；
  - 平台设置的 `save_platform_settings` 等：建任务结果快照要用。
- `#[cfg(test)]` 只在编译这个包自己的测试时生效，rust_api 的测试看不到，所以改成照常导出，注释写明用途。
- 访问策略本来就是这个领域对外的规则，一起导出的还有 `classify_param`、`ParamClass`。

**5. 两个扫路由源码的测试留在 rust_api。**
- `every_route_param_is_classified`、`every_signed_route_without_owned_param_is_reviewed` 要读 rust_api 的路由源码。
- 它们跟登记表 `SIGNED_WITHOUT_OWNED_PARAM` 一起挪到 `api_tests/route_access.rs`，内容不变。
- 新加路径参数还是去 `access.rs` 的 `classify_param` 归类。CLAUDE.md 和协作文档里的路径已经改过来了。

## 怎么保证行为没变

- 三份快照都没变；
- 函数体没有改动，只改了路径和可见范围，挪了一个 trait 实现；
- 测试总数不变（见开发记录）。
