> 顺序见[平台拆包实现记录](./20261016-平台拆包实现记录.md)，AI 排第五

## 做了什么

AI 领域拆成第七个领域包 `retain-pdf-ai`，放在 `backend/packages/retain-pdf-ai`。它管这几样：
- 问答网关 `gateway`、`api`：把阅读助手的问答和运行时配置转给 Python 的 AI 服务；
- Agent 计算 `agent_calculations`、能力令牌 `agent_capabilities`、运行时会话 `agent_runtime_sessions`；
- 文档操作 `document_operations`：受限的页面程序执行器、状态机、浏览器能看的投影 `public_document_operations`。

照样板做：
- 整个目录挪过去，`mod.rs` 改名 `lib.rs` 当门面；
- 路径改成直接写包名：
  - `retain_pdf_api_base::error`；
  - `retain_pdf_core::config`；
  - `retain_pdf_data::db`；
- 门面导出的东西本来就是 `pub`，只有网关的 `base_url` 改成 `pub`（rust_api 用它）；
- rust_api 里写 `pub(crate) use retain_pdf_ai as ai;` 接上，路由、装配里原有的 `crate::services::ai::…` 一行没改；
- 加进 `EXTRACTED_DOMAINS`、工作区成员、`Dockerfile.app` 的两个阶段、合并前的 `cargo test`。

拆之前查过的依赖：
- 不依赖别的领域，`ALLOWED_DOMAIN_DEPENDENCIES` 不用改；
- 除了底座包、`retain-pdf-core`、`retain-pdf-data`，还用 `retain-pdf-proc`：停文档操作的工作进程（查进程在不在、结束整棵进程树）。
  它本来就直接写的 `retain_pdf_proc::…`，不经过 rust_api。

## 和前几个不一样的地方

**1. 网关不再引用 rust_api 的监督器。**
- 网关在 AI 服务不健康时直接返回 503，原来比较的是 `crate::runtime::ai_supervisor::AI_STATUS_UNHEALTHY`。
- `runtime` 在 rust_api 里，包里引用不到。
- 这个常量本来就等于底座包里的 `retain_pdf_api_base::supervisor::SUPERVISOR_UNHEALTHY`（平台拆包时下沉的），现在直接比较这个，值不变。
- 当前状态照旧由装配传进来（`status: fn() -> u8`），网关不自己读监督器。

**2. 只给测试用的导出挂在特性下面。**
- rust_api 的 `api_tests/document_operations.rs` 要直接驱动文档操作，用了 3 个只给测试用的导出：
  - 程序哈希 `canonical_program_sha256`；
  - 控制器 `DocumentOperationControl`；
  - 执行器 `RestrictedPageProgramExecutor`。
- 原来是 `#[cfg(test)]` 导出，跨包看不到。
- 现在改成 `#[cfg(any(test, feature = "test-fixtures"))]`，rust_api 的 `[dev-dependencies]` 打开这个特性，和入口包的测试用 PDF 同一个做法。
- 查过正式构建：`cargo tree -e normal,features` 里 rust_api 只打开了 AI 包的 `default`，没有 `test-fixtures`。
- 这个做法写进了 CLAUDE.md 和 BOUNDARIES.md。之后拆的包，只给测试用的导出都这么写。

## 架构检查

| 规则 | 原来查的 | 现在 |
|---|---|---|
| AI 网关不自己读配置和健康状态（`check_ai_gateway_dependencies`） | `services/ai/` 的 `mod.rs`、`api.rs`、`gateway.rs` 不许 `from_env`、读环境变量、`Lazy`、`ai_service_status()` | 改成查 AI 包的 `lib.rs`、`api.rs`、`gateway.rs`，禁止的写法不变 |
| Agent 计算只用窄依赖（`check_agent_calculation_dependencies`） | `services/ai/agent_calculations` 不许用 `AppConfig`、`AppState`、`api_tests` | 改成查 AI 包的 `agent_calculations/`。`AppConfig` 在 retain-pdf-core 里，包里引用得到，所以还要查 |
| 监督器只许装配和健康检查碰（`check_runtime_ownership`） | 白名单里有 `services/ai/gateway.rs` | 删掉这一条：网关不再引用监督器，包里也引用不到 `crate::runtime` |
| 外面不许点进 AI 的私有子模块（`check_business_private_modules`） | 只管 `ai::gateway`、`agent_calculations::service` 两个 | 整条删掉：子模块在别的包里，本来就是私有的，编译器挡住 |
| 模型要从门面导入（`check_service_model_facade_boundaries`） | `services/ai`、`services/ai/agent_calculations` | 删掉这两条：包里写 `retain_pdf_core::models`，这条规则只认 `crate::models` |

改完以后：
- 往真实代码里故意写违规，两条都报了：
  - AI 包 `gateway.rs` 读环境变量；
  - `agent_calculations/service.rs` 引 `AppConfig`。
- 单测从 62 个变成 58 个：
  - 删了 4 个：私有网关、AI 模型门面、小模块私有路径、小模块模型门面，它们测的规则或条目已经删掉；
  - 网关和 Agent 计算的 2 个改到临时目录里的 AI 包。

## 前端

- 前端没有测试读这个领域的源文件。
- 只有 `frontend/web/scripts/serve_same_origin.py:218` 的注释写着 `services/ai/api.rs`，新位置是 `backend/packages/retain-pdf-ai/src/api.rs`，已经告诉前端会话。

## 怎么保证行为没变

- 三份快照都没变；
- 函数体只改了一处：网关比较的状态常量换成底座包里值相同的那个；其余只改了路径和可见范围；
- 测试总数不变（见开发记录）。
