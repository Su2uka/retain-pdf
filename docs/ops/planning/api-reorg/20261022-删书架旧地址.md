# 删书架旧地址

> 日期：2026-10-22
> 分支：`refactor/drop-library-shelf-old-routes`
> 起因：[书库接口删留](./20261019-书库接口删留.md)定了「前端改调以后删」，前端分支都进了 main（16d13071）。前情见
> [书架冻结与删任务新地址](./20261019-书架冻结与删任务新地址.md)、[合集工作区编号校验与 POST](./20261019-合集工作区编号校验与POST.md)

## 删了什么

| 地址 | 删之前 | 删之后 | 测试 |
|---|---|---|---|
| `GET /api/v1/library/books` | 书架列表（冻结） | `404` | `delete_safety::library_shelf_addresses_are_gone` |
| `DELETE /api/v1/library/books/:job_id` | `DELETE /jobs/:job_id` 的旧地址，OCR 任务 404 | `404`，任务不动 | 同上 |
| `GET /api/v1/library/books/:job_id` | 10-19 已删，`405`（同一路径还有 DELETE） | `404`（路径上不剩任何方法） | 同上 |
| `GET /api/v1/collections/:collection_id/agent-workspace` | `POST` 同一路径的旧地址 | `405`（同一路径还有 POST），不物化、不碰磁盘 | `collection_workspace::get_on_the_workspace_is_405_and_touches_nothing` |

404 还是 405 照 10-19 删 `GET /library/books/:job_id` 的做法：路径还挂着别的方法就是 axum 的 405，不剩方法就是兜底的 404，
不为了状态码好看去挂空处理函数。

代码：

- 登记表：`app/router/library.rs` 整个删了（`router.rs` 不再 merge 它），`app/router/collections.rs` 删 GET 那行；
  处理函数 `routes/library.rs` 删了。架构检查允许名单里只为它存在的 `src/routes/library.rs` 条目删了（只减）。
- 书库包：`books.rs`（书架列表、书架删除、强删前取范围）、`book_projection.rs` 和 `book_projection/`（列表投影、`live.rs`、
  它的测试）删了；`api.rs`、`lib.rs` 门面去掉 `list_library_books_view`、`delete_library_book_view`、`book_delete_job_ids_view`；
  `views.rs` 删 `LibraryBookListView`、`LibraryBookListItemView`、`LibraryDeleteQuery`、`LibraryDeleteResultView` 别名；
  rust_api `models.rs` 不再并进这几个名字。整本删除用的 `job_deletion` 从 `books.rs` 挪进 `documents.rs`（只剩它在用）。
- 任务包：`JobDeletion::scope_ids`、`delete_loaded` 只有书架删除从外面调，改成私有。
- 架构检查：`book_projection` 不存在了，盯着它的规则（任务不许依赖书架投影、`book_projection/artifacts.rs` 不许存在、
  阶段视图和 `job_readiness` 两条规则里的书架投影目录、模型门面规则里的两条路径）删掉或去掉那一项，对应的规则测试改成只测任务那一侧。
- 契约 `library-books.v1`（文件名、`$id` 不变）：删三条书架端点（列表、标了 removed 的单本、删除旧地址），删 `LibraryBookListView`、
  `LibraryBookListItemView`、`LibraryBookDetailView`、`ListLibraryBooksQuery`，以及只给单本详情用的 `ArtifactDisplayItemView`
  （`job-status` 契约里那份不动，两份共有定义的一致性测试名单去掉它）。`title`、`description`、`base_path` 改成现在描述的东西。
  TS 重新生成，`backend/contracts/` 镜像同步。
- 测试：原来走书架删除的删除安全测试（强删取消、409 `job_active` / `job_has_dependents`、清全文索引、pid 复用）改走
  `DELETE /jobs/:job_id`，规则一样；书架 `job_ids` 过滤、书卡标题的测试改看 `GET /jobs`；书架专有的（`job_ids` 不受
  `limit` 限、未知参数不收紧、OCR 任务 404、书架列表的契约键集合、书架和任务列表的进度一致）随接口删掉。
  `scripts/query_acceptance.py` 的列表压测去掉书架三项，搜索那项改测 `GET /jobs?q=`。

## 留了什么、为什么

| 留着的 | 为什么 |
|---|---|
| 契约里的 `JobListView`、`JobListItemView`、`JobFailureBriefView`、`JobProgressView`、`JobStageSnapshotView` 等任务列表类型、两个枚举 | 前端 `frontend/web/tests/contracts/library-books-contract.test.mjs`、`job-failure-brief-contract.test.mjs` 读它们；`job_view_contract.rs` 用它核对 `GET /jobs` |
| 契约里的 `LibraryDeleteResultView`、`LibraryDeleteQuery`（`DELETE /jobs/:job_id` 那条端点） | `frontend/packages/api/src/types.ts`、`jobs-actions.ts` 从 `@retainpdf/contracts/library-books` 导入 `LibraryDeleteResultView`；改名会改前端导入，所以契约里照旧叫这个名字，Rust 侧是 `JobDeleteResultView`、`DeleteJobQuery` |
| 契约文件名 `library-books.v1`、`$id` | 前端测试、`@retainpdf/contracts/library-books` 子路径按名字找它 |
| `classify_param` | 没有只为书架存在的条目（`job_id` 到处在用）；只把它测试里拿书架地址当例子的 `query_references` 换成 `/api/v1/jobs` |
| `POST /collections/:id/agent-workspace` 和 `endpoints!` 文档里「同一地址换方法」的写法 | 写法以后还会用，例子注明这一对 10-22 删了旧的 |
| `routes/library_data.rs`、`library_extras.rs` 等别的书库处理函数 | `/documents`、`/search`、合集、对话，和书架无关 |
| 书名、页数、封面规则（`retainpdf-files` 的 `titles.rs`、任务包 `SummaryCache`） | 任务列表、任务详情、`/documents` 都在用，书架投影只是其中一个调用方 |

书架投影没有被别处共用：`/documents` 书卡、合集工作区（`collection_workspace.rs`，走阅读入口）、AI 工具都不经过它，
`rg book_projection` 删之前只命中书架自己、它的测试、文档和架构检查。
