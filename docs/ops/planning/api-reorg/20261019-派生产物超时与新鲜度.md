# 派生产物的生成时限和新鲜度

2026-10-19，分支 `fix/derived-artifact-timeouts`。修的是
[正确性与状态一致性审计](./20261019-正确性与状态一致性审计.md)明细
[3-磁盘产物与缓存](./20261019-正确性与状态一致性审计明细/3-磁盘产物与缓存.md) 的第 8、9 条，顺带第 7 条的 Rust 一半。

## 问题

- 第 8 条：页预览、封面、缩略图用 `Command::status()` 起 python，没有时限。文件出口共用
  `DownloadGeneration` 的 2 个名额，已受理的生成不因请求断开而取消，卡死两次就占满名额，
  之后所有文件请求（连 `translated.pdf`）都排队，只能重启。
- 第 9 条：对照 PDF、Word、线性化 PDF、页预览的缓存只比修改时间（`产物 >= 每个输入`）。
  生成期间输入被替换，换名出来的产物比新输入还晚，内容却是旧的，一直被当成新鲜；
  修改时间精度粗的文件系统上同一个 tick 里重写输入，`>=` 也判成新鲜。
- 第 7 条（Rust 部分）：封面直接写目标文件，中途被杀留下半截 JPG，之后按「文件在就用」一直命中。

## 决定

1. **页预览、封面、缩略图走和对照 PDF、Word 同一个 `build_with_command`**：时限 60 秒
   （渲染一页，正常几百毫秒到几秒；对照 PDF 120 秒、Word 600 秒是整本书的活）；先写临时文件再换名；
   超时返回 `500` `<名字> builder timed out`，和对照 PDF、Word 超时一样，不新造状态码。
   页码越界的退出码 3 照旧变成 404（`build_with_command_and_exit_check` 先看一眼退出状态）。
2. **`run_supervised` 超时按进程组杀**：子进程 spawn 时自成一组，超时对整组发 SIGKILL。
   以前只 `child.kill()` 直接子进程，Word 导出（pipeline 起 node）、合并译文这类再起子进程的，
   孙进程会活下来继续占 CPU、往产物目录里写。代价：在终端里 Ctrl-C 开发服务器时，正在跑的生成进程
   不再跟着收到 SIGINT，会跑完（或到时限）再退出。
3. **新鲜度按生成前记下的输入戳判断**：生成开始前取每个输入的戳（路径、大小、修改时间纳秒、inode），
   生成完写进产物旁边的 `.<产物名>.inputs.json`，里面还有产物自己的戳（在临时文件上取，换名不改）。
   判断时要求记录在、记录里的产物戳就是现在这份、每个输入的戳和现在一样。
   - 生成期间输入变了：记下的是变之前的戳，这一次照常返回（按请求发出时的输入生成，和请求一致），
     下一次对不上就重新生成。没选「丢弃结果再生成一遍」：Word 一次十分钟，输入一直在变时会一直重来；
     也没选「返回错误」：请求本身没有错。
   - 同一个 tick 里重写：原子替换换 inode，原地重写多半改大小，精度够的文件系统纳秒也不同，都能分出来。
     剩下「原地重写、大小不变、修改时间落在同一个 tick」分不出来，概率可以忽略。
   - 写记录失败不影响这一次请求，只是下一次对不上、多生成一遍。
4. **没有记录文件的缓存照旧按修改时间（`>=`）判断**：这次改动之前生成的缓存都没有记录，全部当作过期的话，
   每本书的 Word 都要重新生成一次（整本几分钟）。它们在输入变了、重新生成以后就有记录了。
   记录在但读不出来、版本不对、对不上，一律当作过期。
5. 封面、缩略图仍按「文件在就用」，不记输入（源 PDF 不变）。合并阅读目录按内容指纹命名，不走这套，没动。

## 范围外

- 审计第 3、4 条（不重渲染的译文修订不进 Word 缓存键、合并指纹）没动：输入集合本身漏了译文 JSON，
  和「输入戳怎么比」是两件事。
- 渲染阶段背景清理缓存的非原子写（第 7 条的 Python 一半）没动。
- 上传时数 PDF 页数的子进程（`retainpdf-ingest` 的 `uploads/pdf.rs`）本来就有时限，没动。

## 对前端

无影响：地址、返回结构不变。卡死的渲染以前是一直等着，现在 60 秒后得到 `500`，在前端就是一次普通的加载失败（图片没出来、下载报错），不用改。
