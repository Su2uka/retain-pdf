# 删掉旧地址

> 日期：2026-10-18
> 分支：`refactor/drop-old-routes`
> - 接在 `refactor/core-views-by-domain` 后面；
> - 合了 `fix/sse-progress-stream-buffering`：实时推送的测试先改到新地址。
>
> 流程：[旧地址用量报表](./20261017-旧地址用量报表.md)

## 决定

用户 2026-10-18 定：删旧地址。登记表里标了 `old` 的 58 个地址全部删掉，不留别名。

删之前的依据：
- **用量**：计数 2026-10-18T08:06Z 清零，到 09:31 共 823 次调用，旧地址 0 次。
- **前端实测**：前端会话在 40001/40011 上点了主页、书详情 7 个页签、3 个任务详情、阅读器，约 70 个不同请求，旧地址 0 个。
  改数据或花钱的按钮（重试、续跑、取消、重跑、改译文、画板）没点，靠代码扫描。
- **代码扫描**：子代理逐个查了 58 个旧地址在全仓库的引用，分成五类：
  - 后端自己生成；
  - 自己的客户端调用；
  - 前端源码调用；
  - 只在测试和 mock 里；
  - 只在文档里。

  前三类在删除前都清掉了：
  - 前端：
    - 单机 OCR 提交改成先 `/uploads` 再 `/jobs`；
    - 原文 PDF 去掉按任务取的兜底；
    - AI 引用的原文页预览改走书的地址；
    - 手动冒烟脚本改到新地址。

    各一个前端分支，前端会话合。
  - 后端：见下面的"顺带改的"。

登记表从 223 个接口变成 165 个，没有旧地址了。

和新地址共用处理函数的，只删登记行。只给旧地址用的处理函数（28 个）一起删，连带删了不再有人调用的：
- 旧产物清单：`build_artifact_manifest`、`JobArtifactManifestView`；
- 旧 Markdown 下载：`MarkdownView`、`MarkdownQuery`；
- `/ocr/jobs` 的建任务、列表、读取；
- 产物名到文件的旧映射。

## 顺带改的

- **查不到书编号时不再退回旧地址**：
  - 任务和书架的 `cover_url`、`thumbnail_url` 给 null；
  - `/files` 的 `source.url` 留空、`ready` 是 false。

  有原文的任务都会登记成书（[任务原文登记成书](./20261017-任务原文登记成书.md)），实际只有原文文件不在的任务会这样。前端确认：
  - 封面只用后端给的地址，没有就显示占位图；
  - 原文没有地址就当没有原文。
- **报错文案**：`/translate/bundle` 带 `workflow=ocr` 的报错原来让人去用 `/ocr/jobs`，改成指向 `/uploads` + `/jobs`。
- **AI 能力令牌**：白名单去掉旧地址。命令行 `retainpdf-agent` 和 AI 服务早已用新地址。
- **自己的脚本**：
  - `backend/api/scripts/query_acceptance.py` 改用 `progress/events`；
  - `tests/performance/pipeline/` 的两个脚本改用 `actions/cancel`。
- **契约**：
  - 去掉 `/ocr/jobs` 三条、旧产物列表和产物清单两条（和只给它们用的 5 个定义）；
  - 去掉 7 处 `deprecated_aliases`。

## 没动的

`/ocr/jobs` 删了以后，"只认 OCR 任务"这个参数恒为 false，但这次没去掉：
- 涉及的位置：取消任务的 `ocr_only`、事件流的 `ocr_only` 和游标里的同名字段、下载的 `JobScope::OcrOnly`；
- 游标编码里带着它，改了会让客户端手里的游标失效，留到以后单独清。

## 删完以后

- 用量报表照旧能跑：登记表里没有旧地址，"还有调用""零调用"两段都是空的；用量文件里旧地址的计数会出现在"不在登记表里"那一段。
- 以后改地址照旧：
  - 先加新地址，旧地址标 `old`；
  - 量用量、和前端确认，再删。
