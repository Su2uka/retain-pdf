# 去掉"只认 OCR 任务"参数

> 日期：2026-10-18
> 分支：`refactor/drop-ocr-only-scope`
> 起因：[删掉旧地址](./20261018-删掉旧地址.md)的"没动的"：`/ocr/jobs` 删了以后这个参数恒为 false

## 决定

用户 2026-10-18 定：去掉。接口的请求和返回都不变，客户端手里的事件游标照样能用。

## 改了什么

- **取消任务**：`cancel_job`、`cancel_submission` 去掉 `ocr_only` 参数。取消 OCR 任务本来就按任务类型分支（排队中直接落"已取消"，过了排队交给 runner 收尾），不看走的哪条路由，行为不变。
- **读任务、读事件**：`job_detail_view`、`job_events_view`、`read_events`、`load_supported_job_snapshot` 去掉参数，一律用 `load_supported_job`。
- **下载**：去掉 `JobScope`，`JobDownloads::open(job_id, JobFile, Disposition)`。同一份文件同时请求只生成一次，靠的是内存里的键，键里少了 `job` 这一段，不落盘，没有兼容问题。
- **底座包**：`load_ocr_job_or_404`、`load_ocr_job_with_supported_layout` 没人用了，删掉。
- **runner 的注释**：原来写 `cancel_job(ocr_only = true)`，改成"取消 OCR 任务时"。
- **顺带**：下载方式里的 `Disposition::Unnamed`（不带 `Content-Disposition`）只有删掉的旧地址用，一起去掉，只剩 `Inline`、`Attachment`。用到它的测试改用 `Inline`，测的是生成和缓存，跟文件名无关。

## 游标

游标是 base64 编码的 JSON，里面有一个 `ocr_only` 字段，解码时不许有多余或缺少的字段。为了不让旧游标失效：
- 字段留在编码里，发出去的游标恒为 false，和改之前一个字节都不差；
- 解码时 `ocr_only` 是 true 的游标拒掉。只有删掉的 `/ocr/jobs/:id/events` 发过这种游标。

加了一条测试：按改之前的格式手拼一个游标，新代码发出的游标要和它完全相同，也要能解开。

真要从编码里去掉这个字段，得升游标版本（`version: 3`），同时让旧版本过期重来。现在没有必要。
