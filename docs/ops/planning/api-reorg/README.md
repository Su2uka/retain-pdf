已经确定的：

- 不上微服务，做模块化单体。（2026-10-15）
- 先固定入口（上传、建任务）和出口（下载、文件），再动流水线。（2026-10-15）
- 文件分组名 `output` / `pages` / `internal`，原文 Markdown 叫 `ocr.md`。（2026-10-15）
- `internal` 组在多用户模式下只给管理员。（2026-10-15）
- 新拆出来的包统一叫 `retain-pdf-<领域>`；现有的包也改名，`retain-jobs` 改叫 `retain-pdf-runner`，
  只改包名不改可执行文件名，在 `refactor/api-freeze-baseline` 合并后单独一次提交。（2026-10-15）
- 拆成 9 个包：入口（ingest）、术语表（glossaries）各自单独成包；模型 token 用量归任务包；
  "按编号读出任务"下沉到底层。（2026-10-15）
- "报告"和"数据"先不合并；"能做什么"和"续跑计划"不合并，只改地址。（2026-10-15）
- 文件列表去掉和 `ocr-provider/result.json` 重复的 `layout.json`；书的文件对外只有
  `/documents/:id/files/…`，内部保留按任务找原文的退路。（2026-10-15）
- 封面、缩略图、预览图是 JPEG，文件名用 `.jpg`（实现时更正）。中间产物下载时的文件名用地址里的
  名字（`/` 换成 `-`），不用磁盘上的原名。（2026-10-15）
- 合并阅读（`merge`）放书库那一侧：在文件之上，单向依赖派生产物；虚拟任务的读取下沉到 `job_loading`。（2026-10-16）
- services 按拆包规划的 9 个领域分目录，领域的 `mod.rs` 是唯一的门面；平台设置归账号，所以账号在服务商上面（规划图画反了）。（2026-10-16）
- 按领域拆包，不再往细拆（任务的 9 类不各成一包）。顺序：先第 6 步问答方法、6.5 改包名，再把 `AppError`、`job_loading` 往下放，拿术语表试点拆第一个包（原规划写从 files 开始），任务最后拆。（2026-10-16）
- 拆包顺序按领域依赖方向排：服务商 → 账号 → 入口 → 文件 → AI → 任务 → 书库。书库依赖任务，只能排在任务后面。（2026-10-16，见平台拆包实现记录）
- Rust 包和 `backend/packages`、`database` 下的目录统一叫 `retainpdf-*`（和 Python 包一样），AI 包也叫 `retainpdf-ai`；应用目录和可执行文件名不改。取代 2026-10-15 定的 `retain-pdf-*`。（2026-10-17，见包名统一为 retainpdf）
