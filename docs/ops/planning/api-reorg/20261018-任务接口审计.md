## 二、要先定一条规矩，再统一改

这几类问题同一种情况各接口做法不同，先定规矩写进 `docs/api/00-约定/`，再逐个接口改。每条后面是建议的规矩。

1. **400 和 409**（B1）：同样是"任务在跑"，cancel、retry-stage 的 refine 返回 409；rerun、resume，以及 retry-stage 的其余阶段返回 400。AI 服务只认 409，用户在任务运行时重渲染只看到"没有提交"。
   建议：状态不允许返回 409，请求体写错返回 400。
2. **"还没产出"**（D2、C3）：有六种写法：
   - 404，文案各不相同；
   - `all.zip` 是 409；
   - 200 加 `null`；
   - 200 加空列表；
   - `available: false`；
   - 200 加全 0。

   "任务不存在"和"报告还没生成"都是同一个 `NOT_FOUND`，前端只能猜。
   建议：
   - 原始文件和报告，没有就返回 404，`error.details.reason` 写 `not_ready`，和"任务不存在"分开；
   - 摘要类（质量、用量、列表）照旧返回 200 和空值；
   - 文件出口的文案统一成 `<名字> not ready`。
3. **分页**（A2、D1、C7）：五种规则：
   - 任务列表没有 `has_more`，`limit` 静默夹到 500；
   - 译文列表的 `limit` 没有上限，`limit=0` 也返回 200；
   - `data`、质量条目的 `limit` 是 1 到 1000，越界返回 400；
   - 事件用游标；
   - 书的任务列表有 `has_more`。

   前端在任务中心用"这一页条数等于 `limit`"来猜有没有下一页，还要自己去重。
   建议：
   - 所有列表都回显实际生效的 `limit`，并给出 `has_more`；
   - 越界统一返回 400；
   - 都只加字段，不改旧字段。
4. **不认识的查询参数**（A3、D10、B8）：
   - `/jobs?q=` 解析成功后被丢掉，前端偏偏发了 `q`；
   - 译文列表的参数拼错了，静默返回全部；
   - `RetryStageRequest` 没有 `deny_unknown_fields`，把 `create_new_job` 写成 `createNewJob` 时，原地重渲染就会变成新建任务。

   建议：
   - 请求体一律 `deny_unknown_fields`，但改之前先查前端实际发了什么；
   - 查询参数先让 `/jobs` 的 `q` 生效，再收紧。

## 六、清理（低）

都不改行为，可以并进上面相关的分支顺手做：
- **调试残留和死代码**（A11、B14）：
  - 建任务路径里有一句调试用的 `eprintln!`；
  - `workflow=ocr` 的分支走不到；
  - `store_upload` 没人调用；
  - 读环境变量的限额函数没人调用，所以 `RUST_API_MAX_JOB_LIMIT` 是死配置；
  - `JobsFacade` 上的 `live_translation_events_after` 重复了一份，没有调用方。
- **测试测的是复制品**（A10）：`views/tests.rs` 测的是 `#[cfg(test)]` 里的一份详情和列表投影，不是线上的 `presentation/`。两边算 `ocr_reused` 的方法已经不一样了。
- **耗时操作占着异步线程**（B11、D12）：好几个读大文件的处理函数直接在异步线程里读，没放进阻塞线程池。
- **小的一致性问题**：
  - `progress/pages/:page` 从 0 数，`files/pages/:page` 从 1 数（B9）；
  - 文件响应没有 `nosniff`（C12）；
  - 有两份 `url_path_escape`，结果不一样（C14）；
  - 列表项和详情里，同一个意思的字段位置、名字、空值写法不一致（A9）。只加不改：列表项加 `document_id`，再写一张两边字段的对照表。
