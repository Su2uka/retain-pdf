# 书架冻结与删任务新地址

> 日期：2026-10-19
> 分支：`refactor/library-books-freeze`
> 起因：书库接口审计（`20261019-书库接口审计.md`）A1，用户定的删留（`20261019-书库接口删留.md` 第一行）；两份在 `docs/library-api-audit` 分支上，合进来后可以改成链接

## 做了什么

| 事情 | 做法 |
|---|---|
| 删 `GET /library/books/:job_id` | 删处理函数、`get_library_book*`、`build_library_book_detail_view`、Rust 的 `LibraryBookDetailView`，以及只给它用的 `book_projection/metadata.rs`、`build_live_projection`。契约测试里对它的断言去掉，改成断言书架列表项没书时不给封面地址 |
| 新加 `DELETE /api/v1/jobs/:job_id` | 放在任务的 lifecycle 类：登记表 `app/router/jobs/lifecycle.rs`、处理函数 `routes/jobs/lifecycle.rs::delete_job`、业务逻辑 `services/jobs/lifecycle/deletion.rs`（任务包 `JobDeletion`） |
| 书架删除标旧地址 | `DELETE /library/books/:job_id` 行尾 `old "/api/v1/jobs/:job_id"`，行为不变 |
| 书架列表冻结 | 登记表说明和文档写「冻结，前端改调 GET /jobs?job_ids= 后删」，契约端点加 `note` |

## 取舍

1. **删除逻辑挪进任务包，书库包反过来调它**。书库依赖任务（`ALLOWED_DOMAIN_DEPENDENCIES`），任务不能调书库，
   所以原来 `retainpdf-library/src/books.rs` 里的删除（范围、`ensure_deletable`、`ensure_no_dependents`、删目录、
   reconcile、重建全文索引）整段挪到 `retainpdf-jobs/src/lifecycle/deletion.rs`。书架删除只剩「读任务，OCR 任务 404」
   这一步再调 `JobDeletion::delete_loaded`；整本删除（`documents.rs`）改用任务包导出的 `ensure_deletable`、
   `ensure_no_dependents`、`remove_path_if_exists` 和 `JobDeletion::remove_job_files`。返回类型 `JobDeleteResultView`
   放任务包 `views/common.rs`，书库的 `LibraryDeleteResultView` 改成它的类型别名，JSON 一样。
2. **旧地址不和新地址共用处理函数**。`/jobs` 的规矩是旧地址紧跟新地址、指向同一个处理函数；这里旧地址要保留
   「OCR 任务 404、提示 `book not found`」，行为和新地址不同，所以留在书库的登记表、用自己的处理函数，只在行尾写 `old`。
   接口目录照样把它列在新地址那一行的「旧地址」列。
3. **单删 OCR 子任务要看父任务**。现在 OCR 任务能删了，`DELETE /jobs/P-ocr` 而父任务 `P` 还在时，父任务的 OCR 产物、
   事件都在子任务里，删了父任务就残了。归到已有的 `job_has_dependents`（`P (uses P-ocr)`），不新开 reason；`force=true` 照删。
   只对工作流是 OCR、编号以 `-ocr` 结尾、父任务存在且不在删除范围里的任务生效，书架删除和整本删除的范围里父子都在，不受影响。
4. **`GET /library/books/:job_id` 是 405 不是 404**。同一地址还挂着 DELETE（旧地址），axum 对路径命中、方法不对的请求回 405。
   为了 404 去挂一个空的 GET 就成了登记表里的假接口，不做。没有调用方，影响为零。
5. **契约里的 `LibraryBookDetailView` 定义暂留**。生成 TS 类型只从 `endpoints` 里出现过的类型出发，删掉端点条目
   这个类型就从 `@retainpdf/contracts/library-books` 消失，前端 `frontend/packages/api/src/types.ts:19` 的重新导出会编译失败，
   `frontend/web/tests/contracts/library-books-contract.test.mjs:66` 也会红。后端不改前端，所以端点条目留着、标
   `"removed": "2026-10-19"` 和说明，定义标废弃；前端去掉这两处引用后再删（写进前端交接）。
6. **新接口不进阻塞线程**。和书架删除一样在异步线程里直接跑库和删目录；书库那批「阻塞活进 spawn_blocking」是
   `fix/library-lookup-errors` 的事，那边改完可以顺手把 `delete_job` 也包进去。

## 对前端

只增不改，前端现在不改也能用。要改的写在 [给前端的交接](../../../core/frontend/backend-changes-handoff.md) 的 `000000000.` 一节。
