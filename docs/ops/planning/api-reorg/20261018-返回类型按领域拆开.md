# 返回类型按领域拆开

> 日期：2026-10-18
> 分支：`refactor/core-views-by-domain`（接在 `main` 197042be 后面）
> 方案：[模块化单体拆包规划](./20261015-模块化单体拆包规划.md)第 5 节第 5 条"共享的返回类型"

## 决定

用户 2026-10-18 定：做拆包规划里留下的最后一条，把核心包里共享的返回类型按领域拆开。

原则：**一个类型放在需要它的最底下那个包里**。
- 只有一个领域（加上 rust_api 的路由、测试）用的请求、返回类型，挪进那个领域包，从包的 `lib.rs` 门面导出。
- 数据库层、事件流也要用的"库里存的记录"留在核心包：任务、上传、文档、术语表、事件。
- 两个领域都用的放在下面那个。比如产物链接，任务和文件都用，文件在任务下面，就放文件包。

rust_api 加了自己的 `models` 门面（`backend/api/src/models.rs`）：
- 原样导出核心包的模型，再把各领域包的类型并进 `models::api`；
- 路由、测试照旧写 `crate::models::api::…`，不用改，也不用知道类型在哪个包。

## 挪到哪

| 原来（核心包 `models/`） | 现在 | 说明 |
|---|---|---|
| `view/`（任务详情、列表、事件、阶段操作、阅读器、实时翻译、译文修订……） | 任务包 `src/views/` | 整个目录挪过去，结构不变。只有任务视图用的分页默认值一起挪 |
| `view/file_paths.rs`（返回给前端的文件地址） | 文件包 `src/links.rs` | 任务、书库都用，放在下面的文件包 |
| `ArtifactLinksView`、`JobActionsView` 这一串和 `build_artifact_links`、`build_job_actions` | 文件包 `src/artifacts/links_view.rs` | 文件包的产物展示也用；放进 `artifacts/`，这是文件包里允许拼产物路径的出口 |
| `UploadView`、`upload_to_response` | 入口包 `src/uploads/view.rs` | |
| `library.rs` 里的请求、返回类型，`view/job_types.rs` 里书架的 6 个 | 书库包 `src/views.rs` | 库里存的记录（`DocumentRecord`、`AssetRecord`、`ConversationRecord`、`MessageRecord`、`CollectionRecord`、`FtsBlockRow`、`BlockSearchHit`）留在核心包，数据库层要用 |
| `glossary.rs` 里的请求、返回类型和转换函数，`ListGlossariesQuery` | 术语表包 `src/views.rs` | `GlossaryRecord`、`build_glossary_id` 留在核心包 |
| `backup.rs` | 平台包 `src/backup/views.rs` | |
| `view/reader_ai.rs`（8 个）、收藏的 7 个类型 | 删掉 | 没有人用：阅读器 AI 的接口、收藏功能早就删了 |

核心包里留下的视图只有三个，都在 `models/view.rs`：
- 事件在库里存的记录 `JobEventRecord`；
- 它的两个字段类型 `JobEventRawView`、`JobEventProgressView`；
- 拼绝对地址的 `to_absolute_url`。

`models/` 从 8364 行减到 4767 行。

没动的：
- `document_operation.rs`：文档操作的记录，数据库层要用；
- `sync.rs`、`ocr.rs`：数据层的同步、OCR 服务商要用；
- `input/`：建任务的请求，各层都用。

## 对外有没有变

- JSON 没变：字段、字段名、顺序、序列化方式都一样，三份快照（接口清单、文件出口返回、建任务结果）没有改动。
- 契约里 `library-books` 有一处说明写的是很早以前的路径（`services/api/crates/...`），改成了现在的位置，`contracts/src`、`dist` 跟着重新生成。

## 前端

前端有一个测试读 Rust 源码：`frontend/web/tests/contracts/job-failure-brief-contract.test.mjs` 读 `job_types.rs` 里的 `JobFailureBriefView`。
- 文件从 `backend/packages/retainpdf-core/src/models/view/job_types.rs` 挪到了 `backend/packages/retainpdf-jobs/src/views/job_types.rs`；
- 前端会话准备一个小分支跟着改，和本分支一起合，否则合进去以后前端测试会红；
- 建议前端改成对照契约里的 `JobFailureBriefView`，不再读 Rust 源码。

另外几处只是注释里提到旧路径，不影响：
- `frontend/packages/domain/src/job-status/types.ts`、`job/types.ts`；
- 两个契约测试的开头注释。

## 规则

CLAUDE.md 加了一条：接口的请求、返回类型放在它所属的领域包里，核心包不再加返回类型。

架构检查不用改。
- 被挪过来的代码有两处直接拼产物路径，要守"只有出口模块能拼"这条：
  - 产物链接放进了文件包允许的 `artifacts/`；
  - 任务视图的测试辅助改走 `stored_path`。
- 冻结名单 `KNOWN_ARTIFACT_PATH_READERS` 还是空的。
