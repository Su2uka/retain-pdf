# 领域门面实现记录

> 日期：2026-10-16
> 分支：`refactor/api-facades`
> 方案：[模块化单体拆包规划](./20261015-模块化单体拆包规划.md) 第 3 节（9 个包）、第 6 节第 5 步后半"每个领域只留一个门面"

## 原来的样子

- `services/` 下有 35 个顶层模块，一个模块一个目录或文件，看不出哪些属于同一个领域。
- 领域外可以一路点进别人的内部，例如：
  - `crate::services::jobs::progress::live_stage::load_live_stage_snapshots`；
  - `crate::services::derived_artifacts::preview::ensure_page_preview`。
- 拆包时每条这种路径都得改，也说不清一个领域对外到底有哪些东西。

## 现在的样子

**按规划第 3 节的表分成 9 个领域目录**，一个领域以后拆成一个包：

| 领域 | 收进来的模块 |
|---|---|
| `accounts` | 原有的 `accounts`；`platform_settings` |
| `providers` | `credentials`、`provider_probe`、`provider_api`、`model_executor`、`model_requests_api`、`model_provider_headers` |
| `ingest` | `uploads` |
| `files` | `artifacts`、`derived_artifacts`、`download_generation`、`download_names` |
| `jobs` | 原有的 `jobs`；`query_execution` 放根目录，`quality`、`usage` 放进 `reports/` |
| `library` | 原有的 `library`；`merge` |
| `glossaries` | 不变 |
| `ai` | 原有的 `ai`；`agent_*`、`document_operation*`、`public_document_operations*` |
| `platform` | `sync`、`backup`、`fonts`、`health_api` |

`document_pages` 只是转手 `retain_core` 的一个函数，删掉了，`library/merge` 直接用 `retain_core`。

**每个领域的 `mod.rs` 就是它唯一的门面**：
- 子模块一律私有（`mod x;`），领域外写 `crate::services::<领域>::<子模块>::…` 编译不过。这一条由编译器守，
  不靠检查脚本。
- 领域外要用的东西，在 `mod.rs` 里标着 `// 门面` 的那一块用 `pub(crate) use` 导出。打开一个领域的
  `mod.rs`，就能看到它对外的全部东西。
- 只给测试用的导出单独放，标 `#[cfg(test)]`。
- 领域里面怎么互相引用不受限制。
- 原来分散在各处的写法都改成从领域根取。例如路由原来写
  `crate::services::platform::fonts::api::list_fonts`，现在写 `crate::services::platform::list_fonts`。
- 一共改了大约 100 个文件的导入，函数体都没动。

**架构检查新加三条**（`check_architecture.py`，配了 5 个单测，单测总数 58 个）：

| 检查 | 管什么 |
|---|---|
| `check_service_domains` | `services/` 下只许有这 9 个领域目录，新模块必须放进其中一个 |
| `check_domain_facades` | 领域 `mod.rs` 里不许出现 `pub mod`，防止有人把子模块改回公开、绕过门面 |
| `check_domain_dependency_direction` | 领域之间的依赖必须登记在 `ALLOWED_DOMAIN_DEPENDENCIES`；多出一条没登记的，或者登记了却没人用，都报错 |

另外：
- 依赖环检查 `check_service_dependency_cycles` 照旧开着。节点从顶层模块变成了领域，以后环就按包来算。
- 往真实代码里故意写违规代码试过，三条都会报：把一个子模块改成 `pub(crate)`、多放一个
  `services/billing.rs`、让 `files` 反过来用 `library`。

## 领域之间的依赖（现状，全部往下）

```
library ─▶ jobs ─▶ ingest ─▶ accounts ─▶ providers
   │        ├────────────────▶ accounts
   │        ├────────────────────────────▶ providers
   │        ├─▶ glossaries
   └────────┴─▶ files
```

**和规划图不一样的一处**：规划第 3 节的分层图把服务商画在账号上面，实际是账号用服务商。
平台设置按规划归在账号里，它保存前要调服务商测连通性，所以账号在上、服务商在下。服务商不用账号，没有环。
以这里和 `ALLOWED_DOMAIN_DEPENDENCIES` 为准，规划文件不改写。

## 顺带清掉的

子模块原来是 `pub` 的，编译器不检查它们有没有人用；收成私有以后，下面这些就露出来了：

- **哪儿都没用的，删掉**：
  - `artifact_resource_path`（按产物名拼旧地址）；
  - `require_upload_path`；
  - `wait_for_terminal_job`（`api_tests` 里有同名的本地函数，不是它）；
  - 二十多个没人用的转手导出，例如 `find_registry_artifact`、`DeepSeekBalanceInfoView`、`sync_root_for`。
- **只有测试在用的，标 `#[cfg(test)]`**：
  - `validate_registry`（任务数据登记表自检）；
  - `job_usage_ledger_path`；
  - `reconcile_unreceipted`；
  - 模型调用的 `Deadlines` 等类型。

## 路由导入白名单变粗了

`ROUTE_SERVICE_IMPORT_ALLOWLIST` 原来写到子模块，例如 `routes/fonts.rs` 只能导入
`services::fonts::api::`。现在写到领域门面，例如 `routes/fonts.rs` 只能导入 `services::platform`。

- **变粗的地方**：路由能拿到门面上给装配用的东西，例如 `BackupService`。
- **没变的地方**：
  - 路由还是只能导入白名单里写的那个领域；
  - 原来写到具体名字的几条，照旧写到具体名字，例如 `routes/common/uploads.rs` 只能导入
    `services::ingest::UploadApiDeps`。
- **以后**：第 7 步拆包时，路由会跟着搬进各自的包（规划第 4 节的接口登记表），这一层白名单到时候就不需要了。

## 怎么保证行为没变

- 分两个提交：先挪目录、改路径，再做门面。
- 两步之后都编译干净（`cargo check -p rust_api --all-targets`，没有警告），测试都全过。
- 接口清单、文件出口、建任务入口三份快照都没变。
