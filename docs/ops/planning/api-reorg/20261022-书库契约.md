# 书库契约 library-documents.v1

> 日期：2026-10-22
> 分支：`contracts/library-documents-v1`（接在 `fix/library-paging-and-unknown-fields` 后面）
> 起因：[书库接口审计](./20261019-书库接口审计.md)第四节，明细 A8、A9、B5

## 做了什么

### 新契约 `contracts/library-documents.v1.schema.json`

把书库这一块现在的返回写下来、钉住，接口行为一点没改。

| 接口 | 请求 | 返回 |
|---|---|---|
| `GET /documents` | `ListDocumentsQuery` | `DocumentListView` |
| `GET /documents/:id` | — | `DocumentRecord` |
| `PATCH /documents/:id` | `PatchDocumentInput` | `DocumentRecord` |
| `DELETE /documents/:id` | `DeleteDocumentQuery` | `DocumentDeleteResultView` |
| `GET /documents/:id/reading` | — | `DocumentReadingView` |
| `GET /documents/:id/translation-coverage` | — | `TranslationCoverageView`（`CoverageSegment`、`CoverageJobView`） |
| `GET /documents/:id/files` | — | `DocumentFilesView`（`DocumentFileEntryView`、`DocumentPagesView`） |
| `GET /documents/:id/metadata-suggestions` | `ListDocumentMetadataSuggestionsQuery` | `DocumentMetadataSuggestionListView` |
| `POST /documents/:id/metadata-suggestions` | `CreateDocumentMetadataSuggestionInput` | `DocumentMetadataSuggestionView` |
| `POST /documents/:id/metadata-suggestions/:sid/apply` | `ApplyDocumentMetadataSuggestionInput` | `DocumentMetadataSuggestionApplyView` |
| `GET /search` | `SearchQuery` | `SearchResultView`（`BlockSearchHit`） |
| `GET /collections` | — | `CollectionListView` |
| `POST /collections` | `CreateCollectionInput` | `CollectionRecord` |
| `PATCH /collections/:id` | `PatchCollectionInput` | `CollectionRecord` |
| `DELETE /collections/:id` | — | `CollectionDeleteResultView` |
| `POST /collections/:id/documents` | `AddCollectionDocumentsInput` | `CollectionRecord` |
| `DELETE /collections/:id/documents/:doc` | — | `CollectionDocumentRemoveResultView` |

写法上的几个决定：

- **空值照 serde 实际写**：类型是 `["x", "null"]` 的键总在、空时是 `null`，写进 `required`；`skip_serializing_if` 的键不进 `required`，
  description 写「没有时键不出现」。`DocumentRecord` 的三个链接在 Rust 里也是 `skip_serializing_if = "String::is_empty"`，
  但接口返回前都会填上（`with_document_media_urls`），所以写进 `required`；只有 `active_version_id` 可以不出现。
- **请求一侧全部 `additionalProperties: false`**：对应上一个分支加的 `deny_unknown_fields`（建、采用元数据建议的两个请求体更早就有）。
  可选字段照 Rust：`Option<T>` 写 `["T", "null"]`（传 `null` 等于不传），有 `#[serde(default)]` 的写 `default`。
- **死字段不删**（A8）：`authors_json`（恒为字符串 `"[]"`）、`year`（恒 `null`）、`doi`（恒 `""`）、`last_opened_at`（恒 `null`），
  description 标「未使用，恒为空」并写清实际空值；测试里也断言了这四个值。删掉就是破坏性改动，留到哪天要真做作者、年份再说。
- **`CollectionMutationResult` 拆成两个定义**：同一个 Rust 类型，删合集只有 `deleted`、从合集拿掉书只有 `removed`
  （另一个键 `skip_serializing_if`），契约里写成 `CollectionDeleteResultView`、`CollectionDocumentRemoveResultView`，两个都是 `enum: [true]`。
  Rust 类型不动（改成两个类型是纯内部重构，不影响线上的键）。
- **枚举收紧到实际值**：`reading_status` 是 `unread | reading | done`（PATCH 校验，库里默认 `unread`），`title_source` 是
  `filename | pdf_metadata | ocr | user`（只有这四处写入），元数据建议 `status` 是 `completed | applied`。前端手写类型里的 `"ai"` 后端没有。
- `removed_paths` 还是服务器上的绝对路径（A8 的另一半），这次只在 description 里写明「只用来排查」，改不改另议。
- 列表键名（`documents`、`collections`、`hits`、`suggestions`）照旧，不统一成 `items`（那是破坏性的）。

### Rust 钉键集合

`backend/api/src/api_tests/library_documents_contract.rs`，照 `job_view_contract.rs` 的写法（那边的几个工具函数改成 `pub(super)` 共用）：

- `book_collection_search_and_delete_views_match_published_schema`：打真实接口，书列表、单本（有版本 / 没版本各一本）、改书名、
  文件清单、阅读入口、翻译覆盖（没有译文）、两条元数据建议（字段填满的键集合 == 全部属性，只有必填项的可选键整个不出现）、
  采用建议、全文检索、合集的建 / 加书 / 改 / 列表 / 拿掉一本 / 删、删书，每个返回都做类型校验和键集合比对。
- `reading_and_coverage_of_a_translated_book_match_published_schema`：一本有译文的书（借 `merged_reading.rs` 的夹具），
  阅读入口、覆盖的段和任务记录（`CoverageJobView` 的空值是 `null` 不是省略）。
- `request_bodies_and_queries_accept_exactly_the_contract_fields`：十个请求类型，拿一个不认识的键去解析，serde 的报错
  （``unknown field `x`, expected one of `a`, `b` ``）里列着它认的全部字段，和契约的 `properties` 比；再把契约字段全填上，必须能解析。
  端点清单里所有 `input`、`query` 都要是 `additionalProperties: false`。

在契约上故意删一个返回键、加一个请求字段、删一个覆盖任务的键，三个测试都红（报出是哪个键）。

### `library-books.v1` 收尾

- 删了 `POST /api/v1/library/books/batch-delete` 的端点条目和 `LibraryBatchDeleteInput`、`LibraryBatchDeleteResultView`。
  `git grep` 过整个仓库和前端的 main、`refactor/library-shelf-to-jobs`、`fix/collection-workspace-post`：只有前端一个对话框的 DOM id
  叫 `batch-delete-confirm-dialog`，没有引用这两个类型或这个地址。`contracts/tests/package-boundary.test.mjs` 加了一条断言它们不再生成。
- `ListLibraryBooksQuery` 加 description 写明冻结：只列了前端发的四个参数；Rust 实际用 `ListJobsQuery`，还认 `status`、`workflow`、
  `provider`、`include_live_stage`，不认识的忽略；`default: 40` 是前端的默认值，Rust 没传时是 20。不补字段（冻结的东西不再扩）。
- `LibraryBookDetailView` 不动：前端 `frontend/packages/api/src/types.ts` 和 `frontend/web/tests/contracts/library-books-contract.test.mjs` 还在用。

### 顺手

- `CollectionRecord.document_count` 的注释说「单条查询恒为 0」，实际每次都现算（`COLLECTION_COLUMNS`），改了注释（A8）。

## 留到下次

- `GET /documents/:id/jobs` 的 `DocumentJobListView`：列表项是任务包的 `JobListItemView`，应该和 `job-status.v1` / `library-books.v1` 共用，
  三份契约里的任务定义怎么去重另议。
- `POST /documents/:id/translate`、`/ocr` 的 `JobSubmissionView`：属于建任务那一块（`create-job.v1` 只有请求体），和 `POST /jobs` 的返回一起做。
- `GET /documents/:id/usage` 不用收：已经在 `token-usage.v1` 里（`UsageSummaryView`）。
- `GET /documents/:id/agent-versions`、`POST /collections/:id/agent-workspace`：多用户下关闭的 Agent 接口，留到 AI 那块。
- 取文件本身的 `/files/:name`、`/files/pages/:page` 返回的是文件，不在 JSON 契约里，`file-responses.txt` 已经钉了响应头。
