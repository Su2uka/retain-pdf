## 做了什么

书库领域拆成第九个领域包 `retain-pdf-library`，放在 `backend/packages/retain-pdf-library`。它管这几样：
- 书、书架、合集；
- 文档（封面、缩略图、元信息建议）；
- 全文检索；
- 对话；
- 合并阅读。

至此 9 个领域都拆成了包，rust_api 的 `services/` 下不再有目录，只剩接上它们的 `services/mod.rs`。

照样板做：
- 整个目录挪过去，`mod.rs` 改名 `lib.rs` 当门面；
- 路径改成直接写包名：
  - 底座包 `retain_pdf_api_base`；
  - `retain_pdf_core`、`retain_pdf_data`；
  - 别的领域写 `retain_pdf_jobs`、`retain_pdf_files`；
- 门面导出的东西改成 `pub`；
- rust_api 里写 `pub(crate) use retain_pdf_library as library;` 接上，路由里原有的 `crate::services::library::…` 一行没改；
- 加进 `EXTRACTED_DOMAINS`、工作区成员、`Dockerfile.app` 的两个阶段、合并前的 `cargo test`。

依赖和 `ALLOWED_DOMAIN_DEPENDENCIES` 登记的一样，书库 → 文件、任务，不用改。两个都已经是包了，所以书库的正式代码一处都不用往外挪。

## 测试怎么分

书库原来有 72 个测试，全部跟着挪进包里，没有要留在 rust_api 的。

其中 3 个测试跟着挪了。它们是拆任务时从任务领域挪过来的"书库视图和任务视图对得上"（`jobs_view_parity_tests.rs`），
现在直接用任务包 `test-fixtures` 特性下的临时库和假渲染器：书库包的 `[dev-dependencies]` 打开它。

另有两个测试用的小工具原来在 rust_api 里，书库包里引用不到，挪到底座包 `retain-pdf-api-base` 的 `test_fixtures`，挂在新加的 `test-fixtures` 特性下：

| 工具 | 原来在 | 谁用 |
|---|---|---|
| `project_venv_bin`：找项目 Python 环境里的可执行文件 | `test_support/python.rs` | 合并阅读的构建测试（真起 Python）；rust_api 的执行器、翻译调试、合并阅读测试 |
| `minimal_pdf_bytes`：一页、指定尺寸的最小 PDF | `api_tests/jobs_common.rs` | 合并阅读的来源、阅读测试；rust_api 里 34 处 |

- rust_api 原来的位置改成转一下（`pub(crate) use retain_pdf_api_base::test_fixtures::…`），原有调用一行没改。
- `project_venv_bin` 按 `CARGO_MANIFEST_DIR` 找仓库根目录。底座包目录比 rust_api 深一层，`../..` 改成 `../../..`，找到的位置不变。
- 查过正式构建：`cargo tree -e normal,features` 里 rust_api 只打开了各个包的 `default`，没有 `test-fixtures`。

顺带删掉 rust_api 里不再有人用的 `crate::job_loading` 转出口：用它的都是 services 里的代码，现在都在领域包里，直接写 `retain_pdf_api_base::job_loading`。

## 架构检查

准备阶段已经把书库的规则都改成逻辑路径，这次只改了三处：
- `DOMAIN_MOUNTS["library"]` 指向包；
- `EXTRACTED_DOMAINS` 加上 `library`；
- `services/mod.rs` 接上。

规则自检没报任何问题。拆任务时已经把只认 `crate::` 写法的规则改成也认包名，这次没有新的。

**往真实的书库包里故意写违规，按包里现在的写法写。** 在临时拷贝里改了 10 个文件，每一处都报出来了：
- `AppState`；
- 自己拼产物路径（`retain_pdf_core::storage_paths::resolve_*`，写在两个文件里）；
- 模型越过门面（`retain_pdf_core::models::job`）；
- 直接读 `job.request_payload`；
- 自己发射任务（`deps.launcher.runtime.launch`）；
- 书库依赖 `retain_pdf_providers`（不允许的领域方向）；
- 碰 `retain_pdf_runner::job_runner`；
- 书的进度不用共用的阶段视图（`book_projection/live.rs` 写 `progress_total`）；
- 展示层自己判断就绪（`book_projection/metadata.rs`）。
