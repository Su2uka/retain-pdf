# 任务接口的规矩和删留

> 日期：2026-10-19
> 起因：[任务接口审计](./20261018-任务接口审计.md)第二节、第五节要用户定

## 规矩

用户 2026-10-19 定，按审计的建议。写进 `docs/api/00-约定/`，以后所有接口都照这个来：

1. **400 和 409**：任务或产物的当前状态不允许，返回 409；请求本身写错了（字段不合法、组合不支持），返回 400。
2. **还没产出**：
   - 原始文件和报告：没有就返回 404，`error.details.reason` 写 `not_ready`；任务本身不存在仍是普通的 404，不带这个 reason。
   - 摘要类（质量摘要、用量、各种列表）：照旧返回 200，空的部分给 null、空列表或 0。
   - 文件出口"还没产出"的文案统一成 `<名字> not ready`。
3. **分页**：所有列表都回显实际生效的 `limit`，并给出 `has_more`；`limit` 越界一律返回 400，不再静默夹。只加字段，不改旧字段。
4. **不认识的字段**：请求体里不认识的字段一律返回 400（`deny_unknown_fields`）。收紧之前先查前端实际发了什么。

已经在用的接口改状态码时（400 改 409、静默夹改 400），先和前端确认。

## 删留

| 接口 | 决定 |
|---|---|
| `POST /translate/bundle` | 删。42000 端口只留 `/health`。 |
| `GET /jobs/:id/ai/reading-path`、`GET /jobs/:id/ai/canvas` | 直接删，连同只给它们用的产物类型和接力逻辑。 |
| `POST /jobs/:id/actions/rerun` | `actions/resume` 作正名，`rerun` 在登记表里标成旧地址 `old "/api/v1/jobs/:job_id/actions/resume"`，行为不变。前端改读 `resume` 以后再删。 |
