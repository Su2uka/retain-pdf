> 挪代码时漏改一处，那条规则就静悄悄地什么都不查。所以分两步：这一步只改检查，不挪代码；下一步再挪。
> 建任务归哪个包另见[建任务归任务包的决定](./20261016-建任务归任务包的决定.md)

## 做了什么

只改了 `backend/api/scripts/check_architecture.py` 和它的单测，Rust 代码一行没动。

### 1. 规则写逻辑路径，实际目录只登记一处

- 任务、书库的规则一律写逻辑路径 `src/services/<领域>/...`。原来 68 处 `SRC_ROOT / "services" / "jobs" / ...` 都改成 `abs_src(Path("src/services/jobs/..."))`。
- 逻辑路径对应哪个实际目录，只登记在 `DOMAIN_MOUNTS`。现在两个都是 `None`，表示还在 `services/<领域>/` 下。挪进包的时候改成：
  ```python
  DOMAIN_MOUNTS = {"jobs": lambda: extracted_domain_root("jobs") / "src", ...}
  ```
  挪进包以后门面从 `mod.rs` 变成 `lib.rs`，`abs_src()` 和 `rel()` 会对上。
- 按目录扫文件改用新的 `scan_logical()`，它会连带扫挂在别处的领域。原来直接 `scan_rs_files(SRC_ROOT)`、`scan_rs_files(SRC_ROOT / "services")` 的 8 处都换了。
- 报错里的路径照旧是逻辑路径（`src/services/jobs/...`），白名单、冻结名单一条没改。`job_runner`、`db` 这些 2026-07 拆出去的模块也是这么做的。

### 2. 规则路径自检 `check_rule_paths`

每次跑检查都会查：
- 规则里写的每个 `Path("src/...")` 都要存在，是文件或模块目录都行。规则要求"不许存在"的路径登记在 `RULE_PATHS_MUST_NOT_EXIST`，登记了却没有规则用，也报错。
- 文件包的那几个相对路径（`FILES_ARTIFACT_*`）也要存在。
- 挪走了的模块（`_CRATE_OF_MODULE`）和挂在别处的领域，不许直接写 `SRC_ROOT / ...`，要经 `abs_src()`、`scan_logical()`。
- 不许直接 `scan_rs_files(SRC_ROOT)` 或 `scan_rs_files(SRC_ROOT / "services")`。

**加上以后马上查出两条早就失效的规则：**
- `check_worker_command_boundary` 扫的是 rust_api 下的 `job_runner` 目录。`job_runner` 2026-07 就挪进了 `retain-jobs` 包，
  这条扫了几个月空目录。改成 `abs_src(Path("src/job_runner"))`，真实代码没有违规。
- `check_state_recovery_boundary` 的后半条查 `src/app/state_recovery.rs`，这个文件早就不在了，所以一直没查。
  恢复函数现在在 `job_runner/startup_recovery.rs`，改成查那里。
- 模型门面规则里的 `src/app/state_recovery.rs` 条目同理，删掉。

### 3. 补单测，并在"已经挪走"的布局下再跑一遍

- 单测工具 `check_sources` 写任务、书库的文件时经 `abs_src()` 落地，挂在哪就写到哪。
  其余模块照旧写在临时的 `src/` 下，另外加了断言：不许写到临时目录外面。
  （改的过程中有一次写到了系统临时目录的上一层，发现后已经删掉。）
- 原来有 10 条涉及任务、书库的规则没有单测，这次都补上了，每条至少一个"写了违规会报"：
  - 下载层不生成产物；
  - 阶段视图只用共用的构建函数；
  - 展示层问就绪状态；
  - 翻译调试读产物；
  - 阅读区域读产物；
  - 汇总读共用文件；
  - 快照工厂不拼命令；
  - 外面经 runtime_gateway 碰 job_runner；
  - `ProcessRuntimeDeps::new` 只在装配里；
  - 模型从门面导入。
- 新加 `MovedDomainMounts`：把 7 组用例在"任务、书库已经挪进包、门面叫 lib.rs"的布局下再跑一遍。
  规则只要还直接扫 rust_api 的 `src/`，这一遍就会红。
- 单测从 58 个变成 124 个：
  - 补的规则单测 10 个、自检 4 个；
  - 挪走布局下重跑的 52 个。

## 怎么验证的

- **新旧检查结果一样**：往真实的任务、书库代码的 4 个文件里写了 8 种违规（`AppState`、碰 `job_runner`、拼产物路径、`ProcessRuntimeDeps::new`、
  模型越过门面、直接读请求字段、翻译调试拼路径、下载层起子进程），旧检查和新检查报的 10 条一字不差。
- **故意改坏能查出来**：
  - 把一条规则改回直接扫 `SRC_ROOT`，挪走布局下的用例红了 3 个；
  - 把一个路径改回 `SRC_ROOT / "services" / "jobs" / ...`，单测红，自检在真实代码上也报。
- **完整彩排**：在临时拷贝里真的把 `services/jobs`、`services/library` 挪进 `backend/packages/retain-pdf-{jobs,library}/src`（`mod.rs` 改名 `lib.rs`）。
  - 只改了三处：`DOMAIN_MOUNTS`、`EXTRACTED_DOMAINS`、`services/mod.rs` 的接上那一行；
  - 检查通过，124 个单测全过；
  - 同样的违规写在挪走后的位置，报的还是那 10 条。
- 其余合并前检查照常跑过（见开发记录）。
