# 产物清单链接换成文件清单

> 日期：2026-10-17
> 起因：[返回链接换新地址清单](./20261017-返回链接换新地址清单.md)第 3 节"这次不换"留下的几项，
> 前端已经把读 `/artifacts`、`/artifacts-manifest` 改成读 `/jobs/{id}/files`，可以换了。
> 分支：`refactor/links-to-files`，合并在前端那一支之后。

## 换了什么

字段名都没动，只是值变了。`{id}` 是任务编号，`{doc}` 是书（文档）编号，前缀 `/api/v1`。

| 字段 | 旧 | 新 |
|---|---|---|
| `artifacts.manifest_path`/`manifest_url` | `/jobs/{id}/artifacts-manifest` | `/jobs/{id}/files` |
| `actions.open_artifacts` | `/jobs/{id}/artifacts` | `/jobs/{id}/files` |
| `links.artifacts_path`/`artifacts_url` | `/jobs/{id}/artifacts` | `/jobs/{id}/files` |
| `links.artifacts_manifest_path`/`artifacts_manifest_url` | `/jobs/{id}/artifacts-manifest` | `/jobs/{id}/files` |
| 产物清单里 `source_pdf` 的 `resource_path`/`resource_url`（知道书编号时） | `/jobs/{id}/artifacts/source_pdf` | `/documents/{doc}/files/source.pdf?download=1` |

- 新地址返回的结构（`JobFilesView`：`job_id`、`output`、`pages`、`internal`）和旧的不一样。
  读这些链接的代码要按 `/files` 的结构解析，不能再按 `ArtifactLinksView`、`JobArtifactManifestView`。
- `source_pdf` 的旧 `/artifacts/<名字>` 默认下载，所以新链接带 `?download=1`。
- 书编号的取法和书库一样：先看任务的上传记录，没有（复用别的任务产物建出来的任务）再查任务表里补写的编号。
  两处都没有，`source_pdf` 还是旧地址。
- 旧的 `/artifacts`、`/artifacts-manifest`（包括 `/ocr/jobs/…` 下的）照样注册，一个都没删。
  下面的目录项等没有新文件名的产物，`resource_path` 也还是旧的 `/artifacts/<名字>`。

## 契约

`contracts/reader-data.v1.schema.json`（和 `backend/contracts/` 下的副本一字不差）：

- 新增接口 `GET /api/v1/jobs/:job_id/files`，输出 `JobFilesView`，另加 `JobFileEntryView`、`JobPagesView` 两个定义。
  字段和 Rust 的 `JobFilesView`（含 `feat/files-view-extras` 加的 `attempt`、`source`、条目的 `updated_at`、`stage`）一一对应：
  - `job_id`、`attempt`、`source`、`output`、`pages` 必填；`source` 和 `output` 的条目是同一个 `JobFileEntryView`；
  - `internal` 只有管理员（和单用户）才有，没有时整个字段不出现，所以不在必填里；
  - `size_bytes`、`updated_at`、`stage`、`page_count` 可以是 `null`（字段始终在）。
- `/artifacts`、`/artifacts-manifest` 两项加 `note`，标明已弃用、被 `/files` 取代。因为结构不同，不算别名，单列一项。
- 生成的 TypeScript 类型（`contracts/src/reader-data.ts`、`contracts/dist/reader-data.d.ts`）已重新生成。

## 测试和快照

  包括 `source`（有书时指向 `/documents/{doc}/files/source.pdf`，`updated_at` 非空）；同时核对任务详情里几个链接都指向 `/files`，
  产物清单里的 `source_pdf` 指向同一本书的文件。

  `source_pdf` 有书编号、没有书编号两种情况各一条。
- 文件出口快照 `file-responses.txt` 重新生成，只改了 10 行，全是上面几个字段：
  每个例子里的 `open_artifacts`、`manifest_*` 两处，加上书任务清单里 `source_pdf` 那一项。
