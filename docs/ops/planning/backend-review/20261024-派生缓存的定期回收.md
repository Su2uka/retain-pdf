# 派生缓存的定期回收

M4 后一半（前一半是[磁盘剩余空间下限](./20261024-磁盘剩余空间下限.md)）。审查原文见[服务端工程审查](./20261024-服务端工程审查.md) M4。

## 定下来的策略（用户选）

只删**能按需重建的派生缓存**，默认关：

- 新配置 `RUST_API_DERIVED_CACHE_RETENTION_DAYS`（默认 `0` 不清），进 `CleanupConfig.derived_cache_retention_days`，
  取值不对照样不启动（M12 的 `env_u64_allow_zero`）。
- 跟着已有的定期清理走（`RUST_API_CLEANUP_INTERVAL_SECS`，默认 6 小时；起服务时先跑一轮）。
- 删什么：
  - 已结束（成功、失败、取消）任务的 `jobs/<任务>/artifacts/` 这一层里：`<任务>-side-by-side.pdf`、
    `<任务>-layout-*.docx`（各个 DPI、各个导出器版本）、`*.linearized.pdf`、`preview-source-p*.jpg`、
    `preview-translated-p*.jpg`，以及它们的记录文件 `.<名字>.inputs.json`。
  - 书的 `documents/<文档>/pages/` 里的页预览和记录文件。
- 按缓存文件自己的修改时间算，生成超过保留天数就删。下次下载、翻页时重新生成（整本书的 Word 要几分钟）。
- 不删：译文 PDF、原文、规范化文档、管线写进 `artifacts/` 的东西（`pipeline_summary.json`、渲染预热、准备阶段……）、
  封面和缩略图（每张不大，书库列表一打开就要几十张，删了是成批重渲染）、生成中的临时文件、排队和在跑任务的缓存、
  符号链接。

## 为什么按名字认

`artifacts/` 不是只放缓存：管线也往里写，删了重建不回来。所以只认生成那边用的文件名。名字收进
`derived_artifacts.rs` 的几个函数（`side_by_side_file_name`、`layout_docx_file_name`、`linearized_file_name`、
`job_page_preview_file_name`、`document_page_preview_path`），生成和回收都用它们；回收的测试拿这些函数生成名字，
生成那边改了名字回收认不出来，测试会红。

## 顺带

- 整轮清理（删事件、删孤儿上传、扫任务目录）以前直接在 async 循环里同步跑，起服务那一轮也是；
  现在都走 `run_cleanup_blocking`（`spawn_blocking`）。
- 数据库加 `terminal_job_ids()`。

## 没做的

- 合并结果（`documents/<文档>/merged/<指纹>/artifacts/`）里的派生缓存：合并目录按内容命名、不可变，
  另有自己的生命周期，这次不碰。
- 打包下载的 zip（`downloads/`、`translated/<任务>.zip`）：每次请求都重新打包，不是缓存，另说。
- 失败任务的中间产物、整个任务目录的回收：用户这次没选（删的是重建不回来的东西）。
- 同一份 PDF 重复上传多存一份。

## 测试

- 文件包 `derived_artifacts::retention`：生成那边的每种名字连同记录文件都删，管线产物、封面、缩略图、临时文件、
  子目录里同名的文件、别的任务的文件都留着；没过期的留着；同名符号链接不跟；任务编号是 `..`、带斜杠、空的什么都不删；
  书的页预览删、封面和 AI 工作区留着。
- rust_api `api_tests::derived_cache_retention`：整轮清理只删成功、失败任务过期的缓存和书的过期页预览，
  在跑任务的、没过期的、管线写的留着；保留天数 0 时一个不删。
- 反向验证：把名字过滤去掉，两边都红（实测）。
