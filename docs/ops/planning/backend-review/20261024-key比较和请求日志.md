# key 比较和请求日志

> 2026-10-24，处理[服务端工程审查](./20261024-服务端工程审查.md)的 M13（一部分）。分支 `fix/auth-key-baseline`（接在 `fix/sync-path-confinement` 后面）。

## 做了什么

- **key 比较**：rust_api（`backend/api/src/auth.rs`）、retain-jobsd（`backend/jobs/src/main.rs`）、助手终端握手
  （`backend/api/src/routes/ai_terminal.rs`）原来都是 `HashSet::contains`，相等比较在第一个不同的字节处就停。
  现在共用 `retainpdf-core` 的 `api_key_matches`：每一把 key 都逐字节比完再合起来，长度不同直接算不等（key 长度不算秘密）。
- **jobsd 没配 key 时**：原来 `api_keys` 为空就放行所有请求。配置加载保证非空，这条路走不到，但写法是"出错就放行"；
  现在和 rust_api、终端一样，空集合谁都不放。
- **请求日志**：`TraceLayer::new_for_http()` 默认的 span 记整个 URI，助手终端握手允许把 key 放在 `?api_key=` 里，
  开 `RUST_LOG=debug` 时 key 就写进了日志。现在 span 只记方法、路径、HTTP 版本（`app/router.rs` 的 `trace_layer`）。
  默认日志级别是 `info`，平时这些请求日志本来就不输出。

## 没做的

- **失败次数节流**：H1 之后非回环监听要求 key 至少 16 个字符，Docker 首次启动生成 64 位十六进制 key，网络上逐个猜不现实；
  单机默认只听回环。按来源 IP 节流要处理反向代理后面的真实地址，收益和复杂度不相称，先不做。
- **终端改成先用 key 换一次性票据**：属于 AI 那一块（助手终端），先不管。
- AI 服务（Python）那边的 key 比较没动。

## 测试

- `retainpdf-core` 的 `config::auth::tests::api_key_matches_only_exact_configured_keys`：两把 key 都能认；空串、少一位、多一位、
  大小写不同都不认；空集合谁都不放。
- `retainpdf-api` 的 `api_tests::request_log`：开 DEBUG 日志，请求 `/health?api_key=query-secret-…`，日志里有 `/health`、没有那个 key。
  反向核对：换回默认的 span，日志里出现 `uri=/health?api_key=query-secret-…`，测试红。
