# 局域网暴露与占位 key

2026-10-24。处理 [服务端工程审查](./20261024-服务端工程审查.md) 的 H1。分支 `fix/docker-placeholder-api-key`。

## 问题

- 交付包 `ops/deployment/docker/delivery/docker/auth.local.json` 和 `web.env` 带的是提交进仓库的公开占位 key
  `replace-with-your-backend-key`。后端非本机监听时只拒绝 `dev-local-key`，占位 key 能用。
- 审查原来的建议是"非本机监听时拒绝占位 key"。细看有两处走不通：
  1. **容器里后端总是监听 `0.0.0.0`**（`app.env`），宿主机端口默认只开在 `127.0.0.1`。后端分不清外面暴露没有，
     直接拒绝占位 key，会让没改过 key 的默认部署起不来。
  2. **换强 key 挡不住 `40001`**：web 容器的 NGINX 给没带 `X-API-Key` 的请求补上后端 key
     （`nginx.conf.template` 的 `$retainpdf_backend_api_key`）。`HOST_BIND_ADDRESS` 改成 `0.0.0.0` 以后，
     能访问 `40001` 的人就有全部权限，包括能在服务器上执行命令的助手终端，key 长短无关。key 只保护直连的 `41000`。

## 决定（用户 2026-10-24 选"堵 41000 + 写清 40001"）

- **自动换掉占位 key**：新的 `docker-compose.yml` 加共享卷 `api_key`，挂到两个容器的 `/run/retainpdf-key`
  （web 只读），两边设 `RETAINPDF_SHARED_KEY_DIR`。
  - app 入口（`ops/deployment/docker/backend/api-key.sh`）：`auth.local.json` 只有占位 key、没设 `RUST_API_KEYS`、
    共享目录可写时，第一次启动生成 32 字节随机数的十六进制（0600）存成 `backend-api-key`，之后沿用；用
    `RUST_API_KEYS` 交给后端（它本来就优先于文件）。key 不打印。
  - web 入口（`ops/deployment/docker/backend-api-key.envsh`，装成 `/docker-entrypoint.d/15-…envsh`，排在官方
    `20-envsubst-on-templates.sh` 前面，被引进来执行）：`RETAINPDF_PROXY_API_KEY` 还是占位 key 时改用那个文件。
    设成空（多用户叠加配置，不让 NGINX 补 key）或换成自己的 key 都不动。compose 让 web 等 app 就绪才启动，那时文件已在。
  - 自己换过 key、设了 `RUST_API_KEYS` 的部署不受影响。
- **旧 compose 兼容**：没挂共享卷的旧 compose 拉新镜像时，两边照旧用占位 key，app 入口和后端各打一条警告。
  所以后端对占位 key **只警告不拒绝**（`AuthRuntimeConfig::placeholder_key_warning`）。
- **后端非本机监听时拒绝短 key**：`dev-local-key` 照旧拒绝，另外拒绝短于 16 个字符的 key（报错只说长度，不回显 key）。
  CI 的镜像冒烟用 `retainpdf-ci-smoke-key`（23 个字符），桌面端、开发栈都监听回环，不受影响。
- **文档写清 `40001`**：交付包 README 写明能访问 `40001` 就有全部权限，要给别的机器用就在前面加带登录的反向代理
  （宿主机 NGINX 示例已有 `auth_basic`），不要直接改 `0.0.0.0`；CLI 示例改成读生成的 key。
- 没做：web 容器自带访问密码（选项里的第二种，用户没选）；单机模式下默认关掉助手终端。

## 测试

- `retainpdf-core` `config::auth`：短 key 只许回环、多把里有一把短就拒绝、报错不回显 key；占位 key 非回环只警告。
- `.github/scripts/tests/test_docker_api_key.py`：用 `sh` 真跑两段脚本（生成、沿用、0600、不打印；没有共享目录时保留占位 key
  并警告；自己的 key、`RUST_API_KEYS` 不动；web 只替换占位 key，空值保持空）；静态核对 compose、两个 Dockerfile、入口脚本接上了，
  占位 key 字面量在交付包、两段脚本、Rust 常量里一致。本机 `sh`（bash）和 `dash` 都跑过。
- **没在真容器里跑**：本机 Docker 守护进程没开。命名卷第一次挂载时从 app 镜像复制目录属主（`/run/retainpdf-key` 在镜像里
  属于 `retainpdf`），这一步靠 Docker 的卷初始化行为；万一目录不可写，入口脚本退回占位 key 加警告，不会起不来。
