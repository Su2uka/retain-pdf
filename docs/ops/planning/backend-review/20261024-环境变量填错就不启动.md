# 环境变量填错就不启动

> 2026-10-24，处理[服务端工程审查](./20261024-服务端工程审查.md)的 M12。分支 `fix/env-parse-errors`（接在 `fix/loopback-clients-no-proxy` 后面）。

## 问题

`retainpdf-core/src/config/env_vars.rs` 的 `env_u64`、`env_u16`……遇到解析不了的值悄悄用默认值，`env_bool` 不认识的值一律当成关：

- `RUST_API_PORT=abc` 照样起在 41000；
- `RUST_API_UPLOAD_MAX_BYTES=200MB` 变成没设，用默认的 512 MiB；
- `RUST_API_JOBS_SUPERVISE=enabled` 当成关；`RUST_API_JOBS_MODE=remtoe` 当成进程内。

服务正常起来，限制却悄悄变成了别的值，很难查。`AppConfig::from_env` 本来就返回 `Result`，可以直接报错。

## 做了什么

- `env_vars.rs`：
  - 数字类：去掉首尾空白再解析；没设、空白、`0` 和以前一样用默认值；设了但解析不了（`200MB`、`abc`、`-1`、超出范围）就报出来，仍返回默认值。
  - 新增 `env_u64_allow_zero`（`0` 有意思的：停机等待、磁盘下限、两项清理），原来三处各写一份，都换成它。
  - 开关：认 `1/true/yes/on`、`0/false/no/off`，别的值报出来。所有开关的默认值都是关，空白照旧是关。
  - 新增 `env_choice`，`RUST_API_JOBS_MODE` 用它：认 `remote`、`in_process`（以及 `in-process`、`inprocess`），拼错的报出来，照旧是进程内。
  - "报出来"：在 `collect_invalid_env` 的范围里就记下来交给调用方（同一个变量只记一次）；不在范围里（启动以后才读的）在 stderr 打一行，每个变量只打一次。
    范围用线程局部变量，`AppConfig` 的组装是同步的，都在一个线程里。
- `AppConfig::from_env`、`from_desktop`：整个组装包在 `collect_invalid_env` 里，有解析不了的变量就返回错误，一行一个列出变量名、取值、要什么样的值，
  rust_api 和 retain-jobsd 都不启动。这个错误排在配置本身的错误前面，后者常常就是前者引起的。
- 两项清理的保留时长（`RUST_API_EVENTS_RETENTION_DAYS`、`RUST_API_ORPHAN_UPLOAD_RETENTION_HOURS`）原来只在 rust_api 起服务时读，启动检查看不到；
  挪进核心包的 `CleanupConfig`，`RetentionSettings::from_env` 从它取。
- 默认翻译并发数（`RUST_API_DEFAULT_*_WORKERS`）建任务时才读，改用 `env_u32`，取值不对时报一次。

查过仓库里桌面壳（`frontend/desktop/src/main/backend-env.js`、`plugins/backend.js`）、Docker（`Dockerfile.app`、`entrypoint-app.sh`）、CI 设的取值，
都是能解析的数字、`1`、`remote` 或路径，不会因为这次改动起不来。

## 没做的

- 审查建议的后一半（把散落的 `std::env::var` 收进 `AppConfig`）：牵涉面大，和"填错了悄悄换值"不是一回事，先不动。
- 启动以后才读的变量（备份间隔 `RUST_API_BACKUP_INTERVAL_HOURS`、同步间隔 `RUST_API_SYNC_INTERVAL_SECS`、默认翻译并发数、`RUST_API_PADDLE_TEMPERATURE`）
  不拦启动，前三个报一次、用默认值；Paddle 温度还是原来的写法（只在 runner 里读，范围 0–2，越界也用默认值）。
- 字符串、路径类的变量没有"解析不了"一说，不变。

## 测试

- `retainpdf-core` 的 `config::env_vars::tests`：数字解析不了时报出来并用默认值，没设、空白、`0` 不算错，`allow_zero` 保留 `0`，
  开关两种写法都认、别的值报出来，`env_choice` 不分大小写，同一个变量只报一次，嵌套的收集各管各的。
- `config::invalid_env_tests::startup_refuses_values_it_cannot_parse`：`RUST_API_SHUTDOWN_GRACE_SECS=3s`、`RUST_API_JOBS_MODE=remtoe` 时
  `from_desktop` 返回错误，错误里两个变量都在；去掉之后正常组装。反向核对：让 `reject_invalid_env` 不拦，这条红。
