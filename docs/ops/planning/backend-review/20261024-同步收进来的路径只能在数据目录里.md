# 同步收进来的路径只能在数据目录里

> 2026-10-24，处理[服务端工程审查](./20261024-服务端工程审查.md)的 M10。分支 `fix/sync-path-confinement`。

## 问题

多设备同步（文件夹或 WebDAV）把别的设备的整行记录写进本机库。文件清单（`files`）早就检查过：只能是相对路径、
不能有 `..`、只能落在 `jobs/`、`uploads/` 这几个目录里。但**行里记着的路径列**没查：

- `uploads.stored_path`、`job_artifact_entries.relative_path`、`agent_calculation_artifacts.relative_path`、
  `document_versions.artifact_key`，以及 `artifacts.artifacts_json` 里的产物路径；
- 发出前，发送方把自己数据目录下的路径换成 `{{data_root}}/…`，接收方再换回本机的数据目录；数据目录以外的绝对路径原样留着。
- 读取时 `resolve_data_path` 遇到绝对路径原样返回，不检查在不在数据目录里（写入时的 `to_relative_data_path` 会拒绝，读取时不会）。

WebDAV 用的是第三方或共享账号时，对方写进来一条 `stored_path` 为 `/Users/<某人>/.ssh/id_rsa` 的上传记录，
下载、建任务这些接口就会去读本机这个文件。改之前写了测试核对过：三条这样的记录都被照收了（`applied: 3`）。

## 做了什么

两层，各管一头：

- **收的时候**（`retainpdf-data/src/sync/files.rs` 的 `path_outside_data_root`，在 `engine.rs` 的 `consider` 里调用）：
  上面这几列，以及产物清单里凡是带 `/` 或 `\` 的字符串（编号、时间、状态里都没有 `/`），去掉 `{{data_root}}` 前缀后
  必须是只由普通名字组成的相对路径：绝对路径、Windows 盘符、`..` 都算越界。越界的整条不收，算进 `rejected`，
  日志里记表、列和路径。正常设备发出的数据都满足这一条。
- **读的时候**（`retainpdf-core/src/storage_paths/path_ops.rs` 的 `resolve_data_path`）：绝对路径必须在数据目录里，
  不许带 `..`；字面比较对不上时（数据目录配成相对路径、经过符号链接，比如 macOS 的 `/tmp` -> `/private/tmp`）
  展开以后再比。越界返回错误，调用方大多当成文件不存在。下载、阅读、续跑、AI 改文档读库里记的路径都经过这里。
- 顺手：同步导出时算文件清单用的 `resolve_stored` 也不再接受带 `..` 的路径（`/data/../etc` 字面上以 `/data` 开头）。

## 影响

- 旧记录里落在数据目录以外的绝对路径（比如很早以前换过数据目录、旧位置还留着文件）不再读得到。
  写入时早就拒绝存数据目录外的路径（`to_relative_data_path`），这类记录只可能来自很老的版本或同步。
- 同步：只有路径越界的记录被拒；越界的记录本来就指着发送方机器上的路径，在本机也读不到正确的文件。

## 没做的

- `jobs.command_json` 没逐列查：runner 重建阶段命令时不直接执行它（审查里也只标了待确认），读取层的限制已经兜住了路径类的读。
- 没改同步的整体模型（整行信任对端），共享账号的风险在文档里写明。

## 测试

- `retainpdf-core` 的 `storage_paths::tests`：数据目录外的绝对路径、带 `..` 的绝对和相对路径、只差一个后缀的兄弟目录都报错；
  数据目录内的旧绝对路径照常解析；经过符号链接的数据目录能对上。
- `retainpdf-data` 的 `sync::tests::rows_pointing_outside_the_data_directory_are_not_applied`：三条 `stored_path` 越界的上传记录
  （`/etc/passwd`、`{{data_root}}/../…`、`uploads/../../…`）都被拒，库里没有这几行；
  `artifact_manifests_are_checked_for_paths_outside_the_data_directory`：产物清单里的越界路径（含嵌套的诊断产物、Windows 路径）能查出来，正常清单不误报。
- 反向核对：去掉收的时候的检查，三条都被收下（`applied: 3`）；去掉读的时候的检查，`resolve_data_path` 那条红。
