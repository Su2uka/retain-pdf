# 桌面壳主进程用 Cordis 试点

**状态：** 试点已实现（分支 `refactor/desktop-cordis-pilot`），待评估是否推广

**日期：** 2026-10-22

**范围：** `frontend/desktop` 的 Electron 主进程；不动 `frontend/web`、后端

## 1. 为什么在这里试

用户看过 DeepSeek Harness 之后，想知道它底下的插件框架 [Cordis](https://github.com/cordiverse/cordis) 能不能
用到我们自己的代码里。Cordis 只能跑在 JS/TS 里，后端（Rust、Python）用不上；前端 `frontend/web` 的装配层不算乱，
真正的问题不在那。桌面壳主进程最合适：

- `main.js` 724 行，大部分是一个 260 行的 `startBundledBackend()`。
- 9 个模块级可变状态：`backendChild`、`aiServiceChild`、`backendStopping`、`frontendGatewayBaseUrl`、
  `suppressBackendCrashDialog`、`splashWindow`、`usingExternalBackend`、`isQuitting`、`childShutdownState`。
- 启动顺序（启动画面 → 后端 → 网关 → 窗口）靠 Promise 链和函数里的先后手排；退出时的收尾在 `before-quit` 里
  手写：哪些子进程要停、按什么顺序、Windows 和 POSIX 各怎么停。

这正是 Cordis 管的事：插件声明依赖（`inject`），依赖到位才启动；注册的副作用（`ctx.effect`）在卸载时按依赖反向撤掉。

## 2. 版本和引入方式

**版本：** `cordis@4.0.0-rc.12`（npm `latest`），加上它唯一的运行时依赖 `cosmokit@1.8.1`。

- 3.x 的 `cordis` 包是带 CLI、loader、logger 的整套（依赖一串 `@cordisjs/*`），核心在 `@cordisjs/core@3.18.1`；
  上游和 dsh 都已经在 4.x 上，3.x 不会再往前走，在 3.x 上试等于试一个要被换掉的接口。
- 4.x 核心包自成一体：一个 52 KB 的 ESM 文件，运行时只引 `cosmokit`（`@standard-schema/spec` 只有类型）。
- 风险：上游 README 写着“API is not yet stable and may change without notice”，dsh 自己也是 vendor 一份。

**引入方式：放进 `src/main/vendor/cordis/`，不加 npm 依赖。**

- `scripts/check-packaging-dependencies.mjs` 明确禁止桌面壳有运行时依赖（`npmRebuild: false` 的前提），而
  electron-builder 怎么从 workspace 提升的 `node_modules` 里收依赖，本地跑不了打包、验证不了。vendor 进
  `src/main/**` 就和别的主进程代码一样被打进 asar，打包规则一条不改。
- 只改了一处：`cordis.mjs` 里的 `from "cosmokit"` 指向同目录的 `./cosmokit.mjs`。`vendor-cordis.test.mjs`
  把这处还原后核对上游 sha256，别处变了测试就红。来源、校验值、升级步骤在 `vendor/cordis/README.md`。
- 体积：两个文件共 64 KB（npm 装的话 `node_modules/cordis` + `cosmokit` 共约 200 KB）。
- 主进程是 CommonJS，Electron 44 自带的 Node 24 支持 `require()` 一个 ESM 模块，实测可用；只经 `src/main/cordis.js`
  一个入口引用。

## 3. 拆成的插件

| 插件 | 文件 | 依赖（inject） | 提供 | 退出时撤掉 |
|---|---|---|---|---|
| ipc | `plugins/ipc.js` | — | — | `desktop:invoke`、`desktop:renderer-issue` 两个 IPC |
| splash | `plugins/splash.js` | — | `splash` { update, close, getWindow } | 关启动画面 |
| backend | `plugins/backend.js` | splash | `backend` { apiPort, external } | 停 rust_api、retainpdf-ai（原 before-quit 的规矩） |
| gateway | `plugins/gateway.js` | backend, splash | `gateway` { baseUrl } | 关网关（不等，免得长连接卡住退出） |
| windows | `plugins/windows.js` | gateway | — | 先藏起所有窗口；撤掉 `activate` 监听 |

- 启动顺序完全由依赖表达：网关等后端就绪，窗口等网关有结果（起来了，或 `baseUrl` 为空退回 file://）。
- 退出：`before-quit` 里只剩“abort 退出信号 → `root.fiber.dispose()` → `app.quit()`”。Cordis 按依赖反向卸载：
  窗口 → 网关 → 后端 → 启动画面，正好是原来手写的顺序（先藏窗口，再停子进程）。
- 原来的 `src/main/*.js` 模块（端口分配、残留回收、Python 运行时、网关、窗口工厂……）一个没动，插件只是把它们接起来。
- `main.js` 从 724 行降到 255 行；模块级可变状态从 9 个降到 4 个（`isQuitting`、`shutdownState`、`appContext`、
  `startupFailureReported`），子进程、网关地址、启动画面窗口都成了插件的局部状态或服务。

## 4. 试点中发现的 Cordis 行为（要写进以后的用法里）

1. **dispose 会等还在跑的 apply。** 插件的 `apply` 是 async 时，卸载要等它跑完才执行 effect 的清理。后端插件等
   就绪最长 90 秒，退出要是发生在启动途中，就得干等。所以后端插件的每个等待都和一个独立的退出信号
   （`AbortController`，`before-quit` 第一件事 abort）赛跑。测试“启动途中退出”在去掉这个信号后会一直挂住。
2. **apply 里抛的错默认不出声。** 插件状态变成 FAILED，但没有任何输出（4.x 的 logger 默认不接控制台）。所以每个
   插件自己接住错误，交给 `reportStartupFailure`（和原来一样弹“RetainPDF startup failed”再退出）。
3. **服务要先 `ctx.provide` 才能读到**，依赖方要等提供方的 apply 完成（状态 ACTIVE）才启动。提供方消失再出现时，
   依赖方会被重建——现在后端只启动一次，不会触发；以后要做“后端崩了自动重启”，得想清楚窗口不能跟着被重建。

## 5. 行为对照

照原样保留：启动画面的进度和文案、端口回收与重新分配、绑定竞争重试 3 次、崩溃弹窗（启动重试期间不弹）、
开发时复用外部后端、AI 由壳监督时不自拉、网关起不来退回 file://、Windows 同步 taskkill / POSIX 先 SIGTERM。

有意的小差异：

- 启动途中退出：原来立刻杀子进程，但启动的 Promise 会因端口等不到而报错，可能再弹一次“startup failed”；现在
  直接放弃启动、不弹。
- 后端就绪到网关起好之间这一小段，后端崩溃也会弹崩溃框（原来要等网关起好才放开）。
- 没有子进程时 `before-quit` 也会先拦一下再退出（多一个微任务的事）。

## 6. 验证

- `frontend/desktop` 的 `npm test`：54 个全过（原有 47 个，新加插件装配 5 个、vendor 校验 2 个），含 lint。
- 实机：Electron 44.4.3 开发模式，用不进产品代码的外壳（`tmp/` 下）隔离 userData、只换掉“回收残留端口”、
  用一个只回 `/health` 的假 rust_api。main 上的代码和试点各跑一次，日志顺序一致：端口重新分配 → 拉起后端 →
  就绪 → 网关 40002 → 主窗口加载 → 自动退出 → SIGTERM → 后端退出。

## 7. 是否推广、怎么回退

**判断标准：** 主进程再加东西（比如自动更新、后端崩溃重启）时，是按“加一个插件、声明依赖”加进去，还是又回到在
`main.js` 里排顺序、加全局变量。

**建议：** 先停在桌面壳主进程，不推广到 `frontend/web`。web 的问题是共用组件重复、请求函数手写，Cordis 解决不了；
而 React 和 Cordis 之间还要再写一层桥。等 Cordis 4 出正式版、再观察一两次桌面壳的改动，再决定。

**回退：** 这次改动只在 `main.js`、`src/main/plugins/`、`src/main/cordis.js`、`src/main/vendor/` 和两个测试文件；
原有模块没动。回退就是 revert 这个分支的提交，不涉及数据和打包配置。
