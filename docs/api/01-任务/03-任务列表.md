# 任务列表

## 接口

```http
GET /api/v1/jobs
```

用于展示最近任务、书库入口和任务卡片列表。

## 查询参数

当前实现支持的过滤和分页能力以接口返回为准。前端应避免依赖本地缓存作为最终状态。

## 响应重点

列表项应包含：

- `job_id`
- `status`
- `display_stage`
- `stage`
- `substage`
- `lane`
- `progress`
- `display_name`
- `page_count`
- `source_file_name`
- `cover_url`
- `thumbnail_url`
- `output_pdf_ready`
- `markdown_ready`
- `bundle_ready`
- `failure`：只有失败的任务才有，成功和进行中的任务整个键不出现（不是 null）。是精简版：`category`、`stage`、`retryable`、`summary` 必有，`root_cause`、`suggestion`、`provider` 没有时键也不出现；不带 traceback，要完整错误去读任务详情的 `failure`。形状见契约 [`library-books.v1.schema.json`](../../../contracts/library-books.v1.schema.json) 的 `#/definitions/JobFailureBriefView`（`job-status.v1.schema.json` 里有同样一份）。`GET /documents/{document_id}/jobs` 的列表项同此。

## 前端规则

- 列表卡片使用列表接口返回的快照即可，不需要立即拉每个 job detail。
- 图片使用 `cover_url` / `thumbnail_url`，为空时由前端使用占位图。
- 不要扫描本地文件系统或拼接 job 目录。
