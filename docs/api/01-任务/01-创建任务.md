# 创建任务

## 接口

```http
POST /api/v1/jobs
```

用于创建 `book`、`translate`、`render` 或只做 OCR 的 `ocr` 任务。

## workflow

- `book`: OCR -> Normalize -> Translate -> Render。
- `translate`: OCR -> Normalize -> Translate，不渲染 PDF。
- `render`: 复用已有产物，只重新渲染。
- `ocr`: 只做 OCR 和 normalize，不翻译、不渲染，见 [OCR-only 任务](../03-OCR/02-OCR-only任务.md)。
  原来的 `POST /api/v1/ocr/jobs` 已于 2026-10-18 删除：先 `POST /api/v1/uploads` 拿 `upload_id`，再用 `workflow: "ocr"` 调本接口。

## JSON 请求示例

```json
{
  "workflow": "book",
  "source": {
    "upload_id": "upload-xxx"
  },
  "ocr": {
    "provider": "paddle",
    "paddle_token": "secret",
    "options": {
      "paddle_model": "PaddleOCR-VL-1.6"
    }
  },
  "translation": {
    "api_key": "secret",
    "base_url": "https://api.deepseek.com/v1",
    "model": "deepseek-flash",
    "workers": 100,
    "batch_size": 1
  },
  "render": {
    "render_mode": "auto",
    "source_cleanup_strategy": "pikepdf_text_strip"
  }
}
```

## 关键字段

- `source.upload_id`: 由上传接口返回。
- `source.source_url`: 远程 PDF URL，取决于 provider 是否支持 URL。
- `ocr.provider`: `mineru`、`paddle`、`local` 或配置型 command provider。
- `ocr.options`: provider-specific 参数，优先放非密钥配置。只能放客户端可填的选项（`GET /api/v1/providers/ocr`
  里 `client_settable: true` 的，或者那里没列出的）；只能服务器定的——本地 OCR 要执行的 `command`、
  `raw_provider`、配置里带 `env` 的——带了返回 400（`ocr.options.command is server-owned; …`，2026-10-22）。
  书的 `/translate`、`/ocr` 和重试的 `overrides.ocr.options` 同样。以前建的任务请求里存着这些键的，
  重跑、阶段重试复制请求时去掉，不报错；它们的值以服务器配置为准。
- `translation`: 翻译模型、并发、术语表和上下文配置。
- `render`: 渲染参数。
- `runtime.job_id`: 任务编号由服务器分配，不要发（留空或不带）。非空会返回 400（`runtime.job_id is set by the server; do not send it`），
  `POST /api/v1/documents/{document_id}/translate`、`/ocr` 同样。
- 书上的两个入口 `POST /api/v1/documents/{document_id}/translate`、`/ocr` 和 `POST /api/v1/jobs` 一样严格（2026-10-19）：
  和入口矛盾的字段直接 400、提示里写着字段名，不再悄悄改掉——`/ocr` 的 `workflow` 只能是 `ocr` 或不写，
  不收 `source.artifact_job_id`、`source.source_url`；`/translate` 的 `workflow` 不能是 `ocr`/`render`，不收 `source.source_url`。
  原文由书自己的上传提供。请求写错先报 400，书不在（404）、要复用的 OCR 不能用（404/409）排在后面。
  以前这个字段可以指定编号，但落库是覆盖式的，传已有编号会冲掉那个任务，带 `..` 还会跑出输出目录。
  服务器兜底：新建任务的编号必须是 `[A-Za-z0-9_-]{1,128}`（不合法 400），库里已有同编号时返回 409。

## 响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "job_id": "20260616120000-abcdef",
    "status": "queued"
  }
}
```

前端拿到 `job_id` 后应开始轮询：

- `GET /api/v1/jobs/{job_id}`
- `GET /api/v1/jobs/{job_id}/progress/events`
