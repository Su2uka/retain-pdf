# 删除任务

`DELETE /api/v1/jobs/{job_id}`（2026-10-19 加，任务类 `lifecycle`）。

删一个任务和它的 OCR 子任务（`{job_id}-ocr`，有的话），**书留着**：文档行、上传、原文 PDF 都不动，
书的「当前任务」（`active_job_id`）改指向剩下的任务，全文索引按剩下的任务重建。要整本删，用
`DELETE /api/v1/documents/{document_id}`。

任何工作流的任务都能删，包括单独的 OCR 任务（以前只能经书架删，书架把 OCR 任务当「不是书」挡成 404）。

## 请求

| 参数 | 位置 | 说明 |
|---|---|---|
| `job_id` | 路径 | 任务编号 |
| `force` | 查询串，默认 `false` | `true`：运行中的任务先取消再删；别的任务还在用它的产物也照删 |

## 返回

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "deleted": true,
    "job_id": "20261019120000-abc123",
    "removed_paths": ["/…/jobs/20261019120000-abc123", "/…/jobs/20261019120000-abc123-ocr"],
    "removed_child_jobs": ["20261019120000-abc123-ocr"]
  }
}
```

契约：`contracts/library-books.v1.schema.json` 的 `LibraryDeleteResultView`（Rust 里叫 `JobDeleteResultView`，
书架删除的 `LibraryDeleteResultView` 是它的别名）。`removed_paths` 是服务器上的路径，只用来排查，前端不要读。

## 错误

| 状态 | 什么时候 |
|---|---|
| `404` | 任务不存在（多用户模式下，别人的任务也是 404） |
| `409` | 不带 `force`，删除范围里有排队 / 运行中的任务（目前没有 `reason`） |
| `409` + `reason: "job_has_dependents"` | 不带 `force`，删除范围之外还有任务在用它的产物：别的任务的 `source.artifact_job_id` 指向它（重新排版的 render 任务、复用 OCR 的翻译任务），或者删的是 OCR 子任务 `P-ocr` 而父任务 `P` 还在。`message` 里列出是谁在用 |

带 `force=true` 删运行中的任务，和 `POST /jobs/{job_id}/actions/cancel` 走同一条路：先登记取消、终止 worker 进程，再删行删目录。

## 旧地址

`DELETE /api/v1/library/books/{job_id}`（书架删除）是它的旧地址，行为不变：同样的范围、同样的 409 和 `force`，
只是工作流是 OCR 的任务照旧 404（`book not found`）。前端改调新地址以后删旧地址，见
[给前端的交接](../../core/frontend/backend-changes-handoff.md)。
