# 失败结构

> 地址已按 9 类整理（新地址如 `/jobs/{job_id}/reports/failure`）。对应的旧地址已于 2026-10-18 删除（返回 404）。新旧对照见 [任务接口分类](../01-任务/04-任务接口分类.md)。

任务失败时，优先读取 job detail 的 `failure` 和 diagnostics 接口。

## 任务诊断

```http
GET /api/v1/jobs/{job_id}/reports/failure
```

## 失败字段示例

```json
{
  "failed_stage": "translation",
  "failure_code": "python_unhandled_exception",
  "failure_category": "translation",
  "summary": "任务失败，但暂未识别出明确根因",
  "detail": "translation review gate blocked",
  "retryable": true,
  "provider": "translation",
  "raw_exception_type": "RuntimeError"
}
```

## 前端规则

- 错误标题优先用 `summary`。
- 展开详情使用 `detail`。
- 是否展示重试按钮参考 `retryable` 和 `GET /jobs/{job_id}/actions`。
- 不要直接把完整 traceback 默认展示给普通用户。
- `raw_excerpt`、`traceback`、诊断 payload 可能已做脱敏。

## 翻译调试

```http
GET /api/v1/jobs/{job_id}/reports/translation
GET /api/v1/jobs/{job_id}/translations
GET /api/v1/jobs/{job_id}/translations/{item_id}
POST /api/v1/jobs/{job_id}/translations/{item_id}/replay
```

这些接口用于排查翻译缺失、模型输出异常、批次失败和 replay，不应作为普通用户主流程依赖。
